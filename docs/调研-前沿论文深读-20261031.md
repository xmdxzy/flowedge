## 一、一页结论：立刻可落地的 10 条

按「能在一周内把代码接进现有 7 条流水线」排序，前 3 条给出实施要点，后 7 条给动作与收益。

### 1. 参考帧挑选 + 镜序重排（GroundShot 思路）
- **论文**：GroundShot, arXiv **2606.20799**
- **一句话方法**：观众判断一致性，是拿「实体后来每次出现」去比对「它第一次清晰出现」；这个首次出现的质量，就是整条片子一致性的天花板。所以别按剧本顺序逐镜拍，要看哪一镜最能把角色拍清楚，先拍它，再把它当参考图喂给后面所有镜。
- **FE 落地动作**：`shotlist` 开机前增加一个「参考镜排序」步骤——按「角色出现面积 × 正脸/全身可辨度 × 无遮挡」给每镜打分，挑分最高的镜作为 `reference_shot` 先生成；生成完抽 1–3 帧存进 `shot-cache/refs/<角色>.png`；后续所有镜的 `ref_images` 从这组帧里取，而不是每次手填。
- **预期收益**：直接压 AGENTS.md 记录过的「第 2 镜漂成黑发女仆」这类身份漂移；把现在靠人肉挑 3 张参考图的动作变成自动产物。
- **工作量**：M（排序打分 + 抽帧 + ref_images 注入链路，约 1–2 天）

### 2. 把「扩写式提示词优化」换成「诊断—定点修复」
- **论文**：TARA, arXiv **2607.18724**；StruPO, arXiv **2610.36146**
- **一句话方法**：失败不是一类，是很多类（数量错、属性串位、关系歧义、文字乱码），每一类要用不同的修复语言；正确做法是先把失败的命题分型，再分派给对应修复算子，最后编译成一条可执行提示词——并且只有一处修复，还要过一道「语义修复门」：改完发现更差就回滚。
- **FE 落地动作**：`prompt_opt` 现在实质是「扩写」，改成三态流水线：`诊断（把 audit 的 FAIL 类型映射成命题级失败）→ 分配（场景锁缺失 / 跳轴 / 光比漂移 / 主体缺失 各一个修复算子）→ 编译（一次只改一个算子，输出结构性 diff）`。第一版不需要模型训练，纯规则 + 一次 LLM 调用即可。
- **预期收益**：修掉 AGENTS.md §0.12③ 记的「用调参掩盖结构错误」——现在改提示词是整段重写，改好改坏说不清是谁的功劳；分型后每轮只动一个变量，天然满足「一轮只动一个变量」的纪律。
- **工作量**：S（规则层 + 提示词改造，半天到 1 天）

### 3. 质量门从「数值代理」升级成「VLM 分级裁判」
- **论文**：Q-Align **2312.17090**(2023 基线)、DOVER **2211.04894**(2022 基线)、FIRM-Video **2608.21839**、VBench-2.0 **2503.21755**、VA-Judger **2608.18607**
- **一句话方法**：让 VLM 输出 `excellent/good/fair/poor/bad` 这种离散等级，而不是 0–100 分（分数会漂、不可比）；打分前先让它「列证据再给分」（check-before-score），压住幻觉打分；美学与技术拆成两个独立维度（DOVER 双分支），别用一个「色温漂移」当全片质量的代理。
- **FE 落地动作**：`verify-media.py` 之外加一个 `judge` 环节：抽 6–8 帧 → 分三问（人物保真、画面技术质量、镜头语言是否达成）→ 每问先要求枚举可见证据，再落等级；等级映射成 0/1/2 参与门控。三问口径与 VBench-2.0 的 Human Fidelity / Controllability / Physics 三维对齐，**不追求复现整套 benchmark**。
- **预期收益**：现在门控只看帧数/响度/静音/色温漂移/ASR 验词，这几项全绿但画面崩的片子照样交付过；加这一层是唯一能拦住「技术指标全绿、内容不行」的手段。
- **工作量**：S/M（判词 + 抽帧 + 阈值，1 天；接进 quality_loop 再 1 天）

### 4. 3×3 多视角拼图做身份注入（ARGUS 的 SMII）
- **论文**：ARGUS, arXiv **2606.11670**
- **方法要点**：把 MLLM 挑出来的多张身份证据拼成 **3×3 stacked mosaic**，作为一份「只读记忆」注入 DiT 的 token 空间，而不是散着喂 N 张参考图（散喂会让身份与姿势/光照/背景纠缠）。
- **FE 动作**：Ref2VA 六段式已经支持多图。加一个预处理：同角色 3 张图（正/侧/全身）先拼成 3×3 网格单图，六段式里只写 `<Picture 1>` 一个引用，并在 `subject_definitions` 里说明网格排布。
- **收益**：减少参考图之间的条件冲突（论文主张的中心瓶颈就是「点参考范式」），参考图 token 数也可控。
- **工作量**：S（一个拼图函数 + 提示词模板改一句）
- **数字**：OpenS2V-Eval Human-Domain 总分 64.38、FaceSim 71.86、NexusScore 51.62、NaturalScore 79.14；HardID-Celeb FaceSim 76.80，YawScore/OccScore 分别 +12.60/+15.10 `[已核实]`（论文自报，**未在本机复现**）

### 5. 双记忆：把「上一镜末帧」也塞进参考
- **论文**：FilmWeaver, arXiv **2512.11274**
- **方法要点**：一致性拆成两件事——镜间一致性（用 shot memory 缓存前序镜的关键帧）与镜内连贯性（用 temporal memory 缓存当前镜的帧历史）。FE 目前只有「角色图」这一路记忆，等于只做了镜间的一半。
- **FE 动作**：`ref_images` 里加一张「上一镜末帧」（若该镜是 `continue` 续接则必加）。这不需要改模型，只是喂图策略。
- **工作量**：S

### 6. 首尾帧对：每镜出两张静帧再 i2v
- **论文**：STAGE **2512.12372**、SmartDirector **2605.27891**、DrawVideo **2605.23508**
- **方法要点**：STAGE 把「稀疏关键帧」换成「每镜一对 start-end 帧」的结构化分镜；SmartDirector 走「低分辨率带多关键帧生成 → 高分辨率关键帧当语义锚做 SR」两段式。
- **FE 动作**：`film` 增加 `keyframe_pairs=true`：用 FLUX 按分镜为每镜出首帧+尾帧，走 FL2VA 首尾帧路径（现在只走首帧）。尾帧同时解决「镜头内运动方向不明确」。
- **工作量**：M
- **数字**：两篇摘要均无量化指标 → **未核实**

### 7. 音乐生成 + 卡点（DiffSynth-Music）
- **论文**：DiffSynth-Music, arXiv **2609.12774**
- **方法要点**：在音乐 DiT 上挂 KV-cache adapter，支持 **beats / vocals / accompaniment / prosody / reference audio** 五类控制；三个模板模型已开源在 ModelScope，支持中文歌。控制缓存算一次、采样全程复用，成本可控。
- **FE 动作**：新增 `music` 节点：把分镜切点时间轴作为 `beats` 条件生成 BGM，长度对齐成片；输出进 `mixBGM`（`bgm_gain` 已有）。**注意**：AGENTS.md 已拍板「知识/科普/产品介绍片不加 BGM」，这条只对氛围片/品牌片开放。
- **收益**：补上「无音乐生成」这一块短板，且 beats 控制能顺手把接缝静音盖掉。
- **工作量**：M
- **数字**：摘要只给定性结论（五类控制依从性提升、歌词保真提升、音质分与基线相当）→ **未核实**

### 8. 训练无关的步级缓存（TeaCache）先做 A/B，别直接上
- **论文**：TeaCache, arXiv **2411.19108**；PromptTea **2507.06739**
- **方法要点**：用时间步嵌入调制后的输入差异，估计输出差异，决定哪些步可以复用缓存——训练无关，即插即用。
- **数字**：Open-Sora-Plan 上最高 **4.41×** 加速，VBench 仅 **−0.07%** `[已核实]`。
- **FE 动作**：**必须做对照实验**：`base 12 步` vs `base 12 步 + cache` vs `PDD 8 步`（现役最快）。因为 8 步方案本来步数就少，缓存的可用空间小，收益大概率远低于 4.41×；若 12 步 + cache 能打平 8 步 PDD 且一致性更好，才值得切。
- **工作量**：M（ComfyUI 侧节点，不改引擎）
- **纪律**：按 §0.4——开关各跑一次，比耗时与峰值显存，日志打印实际生效值。

### 9. 闭环里加「定向重拍」而不是「整镜重掷」
- **论文**：CoAgent **2512.22536**、Thinking on Shots **2608.26809**、SPIRAL **2603.08403**
- **方法要点**：CoAgent 的骨架是 `plan → synthesize → verify`：Storyboard Planner 出结构化镜级计划（实体、空间关系、时间线索），Global Context Manager 维护实体级记忆，Verifier Agent 用视觉语言推理判定中间结果并**只触发选择性重生成**，最后由 pacing-aware editor 调节奏与转场。FE 现在的 quality_loop 是「整镜重跑」，缺的正是「诊断到镜内哪一段/哪个实体」。
- **FE 动作**：`quality_loop` 里把「重跑整镜」拆成三类修复：`改提示词重跑` / `换参考帧重跑` / `只重跑某段（分段生成再拼）`，由 VLM 判定返回类别码。
- **工作量**：M
- **数字**：无量化指标 → **未核实**

### 10. 让裁判先「列证据」再打分（成本最低的一招）
- **论文**：FIRM-Video, arXiv **2608.21839**
- **方法要点**：直接整体打分不可靠且贵；先做「核查」再「打分」，两段式，裁判只对被核查过的维度出分。
- **FE 动作**：所有 VLM 判词模板统一改成「先输出可见证据清单（带时间码/帧号）→ 再输出等级 → 最后一句修复建议」。这一条今天就能改，不写代码。
- **工作量**：S

> 工作量：S ≈ ≤1 天，M ≈ 2–5 天，L ≈ 1 周以上或需训练。

## 三、优先级矩阵（收益 × 成本）

坐标：横轴 = 实施成本（S 便宜 → L 贵），纵轴 = 预期收益（对交付质量的实际影响）。

```
收益高 │  ① 参考镜排序+抽帧     │  ⑥ 首尾帧对（keyframe_pairs）
       │  ② 诊断-定点修复提示词  │  ⑦ 音乐生成+卡点
       │  ③ VLM 分级裁判        │  ⑨ 定向重拍
       │  ④ 3×3 身份拼图        │
       │  ⑤ 上一镜末帧进参考     │  ⑧ TeaCache A/B
       ├───────────────────────┼──────────────────────────
收益低 │  NumeriKontrol 数值控制 │  VBench-2.0 全量复现
       │  MusicLayout 结构表     │  端到端多镜重训
       └───────────────────────┴──────────────────────────
           成本 S（≤1 天）            成本 M/L
```

### 本周就能做的 3 条（都已验证「不需要训练、不需要新权重」）

1. **① 参考镜排序 + 自动抽帧进 `ref_images`**（GroundShot 2606.20799 的思路）
   - 为什么是它：AGENTS.md 已记「只给 characters + 普通提示，第 2 镜会漂成黑发女仆」；问题不在模型，在**参考图从哪来**。现在靠人肉挑 3 张，改成「先拍最容易拍清的那一镜 → 自动抽帧 → 当参考」。改动集中在 `shotlist` 的 plan 排序 + 抽帧 + `ref_images` 组装三处，不碰生成链路。
   - 验收判据：同提示词两镜，第 2 镜抽帧与参考帧做颜色/结构比对（现有一致性门已有 U/V 均值逻辑可复用），并把 `prompt_warnings` 里 `scene_lock_missing` 计数作为副指标。

2. **② `prompt_opt` 改成「诊断—定点修复」**（TARA 2607.18724）
   - 为什么是它：纯提示词与规则改造，零 GPU、零权重；且它顺手解决一条纪律问题——现在改提示词是整段重写，改好改坏分不清；分型后一次只动一个算子，天然满足「一轮只动一个变量」。
   - 验收判据：先跑 10 条历史失败 case 做回归，要求「修复后 audit 全绿率上升，且视频抽帧不被改坏」；记录每条 case 的分型与算子，形成日志。

3. **③ VLM 判词模板改成「先证据、后等级」**（Q-Align 2312.17090 + FIRM-Video 2608.21839）
   - 为什么是它：今天就能改，不写代码。现有 vision 节点已经在做「参考主题」比对，只缺输出协议：强制先列可见证据（带帧号），再落 `excellent/good/fair/poor/bad`，最后给一句修复建议。
   - 验收判据：同一批 20 条片子，新旧判词对比——要求同一片重复判 3 次等级不变（现在是分数会飘）；且至少抓到 1 条「technical 全绿但人被判 fair」的真例。

### 第二梯队（下周启动）

- **④ 3×3 身份拼图**（ARGUS）：一个拼图函数 + 六段式改一句。做完可以和 ① 叠加。
- **⑤ 上一镜末帧进参考**（FilmWeaver）：一行组装逻辑，但对 `continue` 续接镜的收益很大。
- **⑨ 定向重拍**（CoAgent）：需要先有 ③ 的诊断输出，顺序上排在 ③ 之后。
- **⑦ 音乐 + 卡点**（DiffSynth-Music）：只在氛围片/品牌片开放（知识科普片按 AGENTS.md 不加 BGM）。

## 六、一句话总结

这 7 个方向里，**只有「编排层」和「提示词层」在 24GB 单卡上是净收益**——GroundShot 的参考帧调度、CoAgent 的 verify-定点修复、TARA 的分型修复、Q-Align/FIRM 的等级化裁判，全部**不需要新权重、不需要训练**，加起来一周能落三条。而所有「改 kernel / 改结构 / 重训 / 3D 先验」的路线（FPSAttention、Sparse-vDiT、DMD2 自训、端到端多镜、相机轨迹），在当前这台机器上都是负投入——不是论文不好，是硬件不匹配。

FE 真正的瓶颈不是「模型不够强」，是**没有一层把「画面内容对不对」变成可执行诊断的东西**。这是本次调研最确定的一条结论。
