## ① 一句话结论

FE 最该吸收的**两条编排层做法**：

1. **把「相邻镜续接」从隐式约定升级成显式契约对象**（`ComfyUI-MiniMax-H3-LongMedia` 的 `GENERATED → 复用原生 TAKE 潜态` / `MEDIA → 只 VAE 编码尾部窗口当 frame-0 keyframe` 二分法）。FE 现在只有「xfade 重叠秒数」一个量，**没区分「同潜空间续接」与「外来素材接边」**，这是多镜身份漂移的结构性缺口。
2. **显存/量化路由必须按「物理打包体积 + 激活余量」判档，不能按 BF16 逻辑尺寸或分辨率倍数**（LongMedia `auto` memory_mode 明文；FE 现判据只有「>1.15× 608×352×124 基准」）。

其余：ComfyUI 侧值钱的是**帧插值（CPU 替代已有）**与**逃生舱模板自带 `models` 清单**；AI 剪辑侧能变 FE CPU 道节点的是 **PySceneDetect、whisperX、DeepFilterNet、VMAF**；评测侧唯一命中 FE 已知缺口的是 **VBench-2.0 `Human_Identity`**。

#### ★ 专项：`ComfyUI-MiniMax-H3-LongMedia`——与 FE 同模型、同一条路的编排层

**本次最值钱的发现。** 星 309、推送 2026-09-29、版本 **0.6.63**、Comfy PublisherId `noise`（可走 Comfy Registry 装）。节点【自述】：`Setup` / `Planner` / `Director` / `Cameras` / `Sampler` / `Decode` / `Video Reconstructor`。

语义契约：`h3_mode` = `t2va`/`fl2va`/`ref2va`/`hybrid`/`video_ref_edit`（FE `text2video` 内部已分流 t2va/fl2va/ref2va）；`timeline_mode` = `single`/`segmented`/`multiclip`（FE 对应「单镜 / 多镜批量构图 `batch_size`」）；`duration_source` = `auto`/`video`/`audio`/`manual`/`longest_input`（**FE 无此概念，时长由 plan 定死**）；`memory_mode` = `auto`/`normal`/`low_vram`/`ultra_low_vram`（FE 只有 LowVRAM 布尔）。

**续接契约（★ 第 1 条结论来源）【自述】**：`GENERATED → GENERATED` 复用保存的**原生 TAKE 潜态**；`MEDIA → GENERATED` 时**外部素材永不成为扩散目标**，只把**剪辑尾部窗口** VAE 编码，作为**原生 frame-0 keyframe** 挂到新目标；外部续接缓存**按「媒体指纹 + 裁剪区间 + 目标几何 + 重叠」四元组作键，tail state 存 CPU**。
`MultiClip`：每镜独立 prompt/duration/seed，`clip_id` 稳定；**Global Prompt 承载全序列不变项**（角色身份、服装道具、环境、风格、光照逻辑、氛围），镜卡只写「这一段时间发生什么」；建议 4–8s（高控制）/ 7–12s（通用）/ 12s+（边界少但漂移机会多）。**相机指令先从 Planner 文本剥掉**再追加编译后的相机指令，避免「两套取景/运动主张打架」。**RefMod**（0.6.55+）：从素材/所选镜/TAKE 造**可复用原生 H3 视觉+音频参考**，与文本嵌入、物理 TAKE 续接**互相独立**（「Character RefMods retain identity authority across MultiClip」）。`Loop Closure` 在潜空间把尾部落回首帧宏观态，**不是 RGB crossfade**。

**显存/量化路由【自述】**：
- `auto` **不按 BF16 等价逻辑尺寸判档**（「Quantized H3 is not routed from BF16-equivalent logical `model_size` alone」）——分开算「打包物理权重 + scale/未量化张量 + 激活余量」。明文后果：量化权重报 30+GB 逻辑尺寸**不会**把 16GB 卡降成 `ultra_low_vram`。
- **保留 ComfyUI Dynamic VRAM**：「Do not use `--disable-dynamic-vram` for normal production runs」（与 FE 实测「关掉无正收益」一致——FE 是试出来的，这里是设计前提）。Windows 大 safetensors 沿用 `ModelMMAP`/`TensorFileSlice` **文件映射**，**不做**「先 pread 20–30GB state_dict 进系统内存」的土办法。
- **重复排队必须重置驻留假设**：每次 `prepare_sampling()` 前建 execution-memory boundary（同步 CUDA、清 prefetch 队列、重置 cast buffer、重置 AIMDO/VBAR 水位、释放旧模型驻留与 allocator cache、清瞬态 CUDA 引用与 FastH3/VSA 几何缓存）。理由原文：「Repeated identical Queue runs should therefore start from the same residency assumptions instead of **monotonically increasing** the LongMedia-owned baseline.」
- `normal` 模式下 **`0` 是真关闭**（不是回落默认），正 MLP 值最高 131072 原样送达；16GB 级 native INT8 **门控投机式 `prefetch_dynamic_vbars`**。原文：短固定分段「provide better throughput/stability than an enormous single packed sequence」；`reference_budget=low`。
- **可抄判据**：「A failure inside `prefetch_queue_pop` is different from a fused-QKV allocation failure and should be treated as a **transport/residency** issue rather than "fixed" by changing attention math.」

**兼容层**：stock H3 / native INT8·W4A8 权重 / H3ddle FastH3 VSA / Kijai FastVideo VSA；**结构化探测，契约不满足就 fail closed**。
**LoRA：README/docs 全文未提**（【未取到】）。
