### 2.7 横切一：渲染吞吐（可核实的数字全列）

| 来源 | 数字 | 口径 | 性质 |
|---|---|---|---|
| **FE 生产实测** | 18s / 1080p / **432 帧 → 21.3s**（workers=2） | ≈ **20.3 fps 墙钟**，≈49 ms/帧 | **一手**（AGENTS.md，非本轮） |
| FE 生产实测 | 4s / 720p 整 run 4.3s | 短视频场景 | 一手（同上） |
| FE 源码注释 | 1080p/24fps **单 worker ≈0.1s/帧**；`still` 实测 200 ms（含冷启动） | 10 fps/单 worker | **一手**（源码注释） |
| FE 超时策略 | `60s + duration×fps×0.25s`，硬上限 30 min | 0.25 s/帧 保守预算 | **一手**（源码） |
| lemo 官方 | 默认 3 worker；**单独渲染可上 6** | 吞吐随 worker 近似线性 | 官方原文 |
| lemo 官方 | 「Capture is fast because of **JPEG screenshots**, **one browser per worker** and **grain added in ffmpeg**：**页面里画颗粒会让每帧不可压缩、变慢**」 | 设计原理 | 官方原文 |
| **HyperFrames 官方** | **25.0s vs 9.8s**，1920×1080、**300 帧**、三次中位数；「one CSS declaration is the whole difference」，像素比对确认画面未变 | best ≈**30.6 fps**，worst ≈12 fps | **官方自述**（非本机） |

| Manim / Motion Canvas / Revideo / editly / moviepy / Blender / Rive / Lottie | **未取到可比数字** | — | §⑤ |

**结论**：lemo 与 HyperFrames 同量级（十几～三十 fps @1080p）；**FE 现有链路已达这条赛道的正常水平**，换方案不会带来数量级收益——收益在**确定性保障、排版质量与质检**，不在速度。

### 2.8 横切二：确定性

| 方案 | 机制 | 证据强度 |
|---|---|---|
| **lemo** | 明文契约：**禁 `Date.now()`、禁无种子 `Math.random()`、禁跨帧带状态**；「任何帧可被任意 worker 单独、任意顺序渲染」；`core/lib.js` 提供 `mulberry`/`hash` | **官方原文** + **FE 模板铁律复刻**（`kit.js` 首行注释与 `hash`/`rng` 实现，一手） |
| **HyperFrames** | 独立 Determinism 页：`time = floor(frame)/fps`（**整数运算，绝不读时钟**）→ `seekFrame()` 把动画 seek 到位（**paused and seeked, never played**）→ `HeadlessExperimental.beginFrame` **原子抓取**（无半绘制帧）→ FFmpeg 编码混流；**资产首帧前全部加载**；另有 `--docker` 求确定性输出 | **官方原文** |
| **机制对比点（关键）** | lemo/FE 是「**evaluate 后截图**」——页面若有异步绘制，可能抓到中间态；HyperFrames 是「**seek 完再原子抓**」，语义更强 | 来自两份官方文档，**未做像素级 A/B** |
| **Motion Canvas** | 官方渲染文档写「play through the animation」——**播放式**，与「任意帧可独立渲染」的强确定性不同（风险，见 §⑤） | 官方原文（措辞） |
| **Revideo** | README 无确定性契约，仅「zero dep 核心 + 并行分片」 | **未取到** |
| **Remotion** | 帧号驱动 + `delayRender()` 阻塞门（`--timeout` 默认 30 s）；完整确定性表述本轮未逐字取证 | 部分（CLI 文档） |
| **Manim** | 场景是时间的函数，构造上确定；OpenGL 后端是否逐帧等价**未核实** | 未取到 |
| **Satori** | SVG 生成为纯函数；栅格化确定性取决于所选栅格器 | **未核实** |

### 2.11 横切五：中文字体与排版的坑（本轮最高价值发现）

| 事实 | 出处 | 对 FE 的影响 |
|---|---|---|
| **lemo 官方规则**：`core/fonts/` 的中文显示字体**只有约 200 字形，不够正文**；中文必须**自行子集化**（Google Fonts CSS API 带 `&text=` 只取用到的字）→ 下载到项目 `fonts/` → `@font-face` 自托管；**「don't link Google Fonts at render time」** | **官方原文** TECHNIQUE.md（一手读） | 这是 lemo 自己的纪律 |
| **FE 现状违反该纪律**：`kit.js` 的 `SANS = '"Microsoft YaHei", "PingFang SC", "Noto Sans SC", "Source Han Sans SC", sans-serif'`；`MONO = '"Cascadia Mono", Consolas, "Courier New", monospace'`；`darkcard/index.html` 另写 `"Microsoft YaHei","PingFang SC"` | **一手源码** | 三重后果：① **机器相关**——换台没雅黑的机器，字形/字宽全变，**跨机不确定**；② **静默回退**——Canvas `ctx.font` 字体缺失时**永不报错**，只会默默换字体；③ **版式漂移**——`fitText`/`wrapText` 用 `measureText` 量宽，字体一变**换行点与字号跟着变** |
| 渲染期字体加载时序 | lemo：`window.READY` **必须等字体与图片加载完**，工具最长等 **180 s**；HyperFrames：**「每个资产都在首帧之前加载完」**、禁 mid-render fetch；Remotion：`delayRender()` 默认 **30 s** 超时 | 任何 web font 方案都必须把「字体就绪」纳入 `READY`/`delayRender` 门，否则**首帧起就错版** |
| `readcheck.mjs` 把**中文阅读速度**参数化 | 官方原文：文字须完整留画面「**CJK 字 ÷ 4.5 + 其他非空格字符 ÷ 15 + 1.5 s**」以上，且不低于 `--min` | FE **没有**等价门 → 中文字幕/要点卡可能「停留不够读」而无人报警 |

**最小修法（不改渲染器）**：把 `kit.js` 的字体常量换成**随模板内嵌的子集化 web font**（`@font-face` 指向 demo 目录内 woff2），并在 `window.READY` 里等 `document.fonts.ready`；`codetpl/` 由 `go:embed` 内嵌，字体文件随模板落盘即可。**收益**：跨机确定性 + 可复现版式。

### 2.12 lemo 横评：FE 用的是它哪一层？覆盖不到什么？

**lemo 完整分层（一手读 `core/README.md` + `TECHNIQUE.md`）**

```
timeline（唯一事实源）
  ├─ picture : index.html + render(t) → headless Chrome 逐帧 → video.mp4
  ├─ voice   : TTS(逐句) → ASR 验词 → 词级时间戳
  ├─ music   : 同一 timeline 出的配乐（采样 + 拨弦建模）→ stems
  ├─ sound   : 按事件时刻的程序化拟音
  └─ subtitle: .srt + 烧录
mix（duck/compress/balance）→ ffmpeg 两遍 loudnorm −14 LUFS → film.mp4
```

| lemo 层 | **FE 是否用** | 证据 |
|---|---|---|
| 页面契约 `READY`/`render(t)`/`DUR` | **用 3 个**；**未用** `TEXTS` / `EV` | 一手源码：FE 模板只实现前三者 |
| 渲染器 `core/render/video.mjs`（JPEG 截图 → mjpeg → libx264 crf14 → 分片 concat -c copy） | **完全用** | 一手源码：`code_video.go` 直接 spawn 该脚本 |
| `readcheck.mjs`（**文字可读性 / 版面越界门**） | **未用**（模板不导出 `TEXTS`，跑也只会 exit 2） | 官方原文 + 一手源码 |
| `mux.sh`（两遍 loudnorm、true-peak、颗粒、静音告警、**绝不留下半成品**） | **未用**（走 FE 自家 `masterLoudness`/`mixRoomTone`） | 官方原文 |
| 语音合成 `tts.py`/`tts_zh.py` | **未用**（FE 用自己的 Kokoro 装配） | — |
| 语音验词 `asr_check.py`（含**词级时间戳**） | **未用**（FE 在 H3 台词镜有 `verifyDialogueLine`，但 code_video **无旁白验词**） | 一手 readme |
| 拟音/配乐 `sfx.py`/`sampler.py`/`pluck.py` | **未用** | — |
| `srt.py` + 烧录字幕 | **未用**（FE 有 `subtitles.go`，与 lemo 各写一份） | 一手 |
| 后处理 `core/three/post.js`（景深/GTAO/bloom/色彩分级/2× 超采样）、`core/post/crt.js`（WebGL2 CRT/VHS） | **未用** | 一手 |
| `still.mjs` / `events.mjs` / `sheet.py` | **未用** | — |
| 中文字体纪律（自托管子集化 CJK） | **反向**（用系统字体栈） | 一手源码 |
| 美术风格库 `styles/`（**60 个目录**，含 `_template` ⇒ **59 种风格**，各带 `STYLE.md`） | **移植 4 种**，且**全部为 Canvas 2D 重写** | 一手：`styles` 目录数=60；`codeVideoStyles`=4 |

**结论：FE 用的是 lemo 的「页面契约 + 渲染器」（约 2/16 层），其余 14 层全部自研或空缺。**

**lemo 覆盖不到、别家更好的地方**

- **高质量 HTML/CSS 排版**（表格/网格/盒模型）→ **HyperFrames**、Remotion（FE 的 4 个模板全是 Canvas 2D 手绘坐标，等于放弃这层）
- **真正的 mp4 素材回放** → **Remotion `OffthreadVideo`**（FE 已实测「视频只显示成一帧图片」是痛点）
- **原子帧捕获**（避免抓到半绘制帧）→ **HyperFrames `beginFrame`**
- **无浏览器路线的排版渲染** → **Satori**（HTML/CSS→SVG，Taffy 做 Flexbox/Grid）
- **公式/数学动画** → **Manim CE / ManimGL**；**3D 与景深/体积光** → Blender（重）、three.js 直写（lemo 有但要 GPU + 官方建议 WSL）
- **设计师资产（AE/Rive）** → **Lottie / Rive**

**lemo 的独占优势（本清单内未见等价实现）**：① `readcheck` 的**中文阅读时长/版面越界门**（「CJK 4.5 字/秒」未见别家官方文档）；② **一条 timeline 同时驱动画面/配音/配乐/拟音/字幕**；③ **59 种带美术指导文档的风格库**；④ 「**按 twos 动画**但相机与光照逐帧平滑」这类美术级规则。

### 2.13 FE 现状事实清单（一手，供父会话对冲简报）

- **风格 / 渲染参数（一手，附行号）**：现为 **4 种**（`blueprint`/`darkcard`/`atlas`/`studio`），`knowledge_film` 默认 **`darkcard`**；共用工具是 **FE 自研**的 `codetpl/shared/kit.js`（非 lemo 的 `core/lib.js`）。渲染命令 `node core/render/video.mjs <demoDir> --fps 24 --workers 2 --out <abs> --size WxH`、`cmd.Dir=LEMO_HOME`（L154-168）；workers 默认 **2**/上限 **6**（L146-152）；超时 `60s+duration×fps×0.25s`（L298-308）；输出 `data/generated/code-video-<unixnano>.mp4`、`tts_text` 非空才配音且**默认无声**（L117-127/L183-203）；库定位 `LEMO_HOME`→`D:/AI/lemo-opuscar`→`%USERPROFILE%/lemo-opuscar`、**找不到就报错不静默降级**（L267-285）；live 冒烟 `FLOWEDGE_LIVE_CODEVIDEO=1` 遍历 `codeVideoStyleNames`——**加了风格却忘了加进这个切片，测试不会覆盖**。
- **go:embed 陷阱**：共用目录必须叫 `shared`，**不能叫 `_shared`**——`go:embed` 跳过 `_`/`.` 开头的文件与目录 → **编译通过但运行期文件不存在**（`code_video.go` L224-225 注释，已踩）。
- **两个页面契约坑**：① canvas 是 **1920×1080 设计稿**，须按视口等比缩放（`--size` 只决定截图尺寸），否则小分辨率**裁掉右下标题栏**；② `body` 必须 `width/height:100%`，否则 canvas 无法 `position:absolute`、**画面全黑**。

## ③ 与 FE 的对接点

### 3.1 结论先行

| 问题 | 回答 |
|---|---|
| **该不该换掉 `code_video` 节点？** | **不换。** 现有链路是本机实测过的（18s/1080p/432 帧 → 21.3s），吞吐与 HyperFrames 同量级；换掉只会用未知换已知，并丢掉「CPU 道并行、与 H3 不抢显存」这个**混合出片的效率支点**。 |
| **最值得「加」的是哪个？** | **HyperFrames**（Apache-2.0、agent 原生 CLI、独立确定性契约、HTML/CSS 排版层、`--batch` 一变量一产物、`--json` 便于 Go 解析）→ 做**第二渲染后端**，把复杂排版卡从手绘 Canvas 迁到 HTML/CSS。 |
| **第二优先？** | **Remotion**，**只用于含真实素材的产品介绍片**（`OffthreadVideo` 解决「视频显示成一帧」）。**先答一个产品形态问题**：FE 是「本地自用」（免费）还是「对外产品」（落 Automators 计费）？ |
| **明确不建议？** | Motion Canvas（**渲染依赖编辑器 GUI**，自动化不友好）、editly（停更 1.5 年）、moviepy（给 Go 单 exe 引 Python+numpy）、ffmpeg-python（零增量）、vidgear（不适用）、pireel（AGPL）。 |

### 3.2 路线 A（不改架构，只补三处短板）——**推荐先做**

| 短板 | 改哪里 | 收益 | 风险 |
|---|---|---|---|
| **中文字体不是自托管** | `codetpl/shared/kit.js` 的 `SANS/MONO` 常量 + 各风格 `index.html` 的 `@font-face`；woff2 放进 `codetpl/shared/fonts/`（随 `go:embed` 内嵌） | 跨机版式**确定**；消除「换机换字」与 `ctx.font` **静默回退**；`fitText/wrapText` 测量变可靠 | 字体进 exe 体积增加；按文案预生成子集（**未验证**：可变字重/多语言混排的子集策略） |
| **无文字可读性门** | 给 4 个模板加 `window.TEXTS(t)`（返回 `[{id,text,x0,y0,x1,y1}]`），再调 lemo `readcheck.mjs` | 中文字幕/要点卡的「停留够不够读」**自动拦**（**本清单内无等价能力**，独占） | 模板要暴露文字盒 → 4 个模板都要改；`readcheck` 是**外部 Node 工具**，需新起进程 |
| **无旁白验词** | `code_video.go` 的 `tts_text` 分支后加一步 ASR 校验（复用 FE 的 faster-whisper） | 中文旁白错字**当场拦**（同 lemo `asr_check.py` 思路；FE 在 H3 台词镜已有 `verifyDialogueLine` 的成熟度证据） | 多一次调用；阈值需按 FE 的 `stripASRPunct` 口径调 |

### 3.3 路线 B（加 HyperFrames 作第二后端）——**推荐第二个做**

**改哪里（4 处，可枚举）**
1. `backend/service/code_video.go`：加 `backend` 分支（`lemo` 默认 / `hyperframes`），新增执行器（如 `execCodeVideoHyperframes`），保持 `CodeSpec → HTML 变量` 映射；**产物仍回 `map[string]any{"video": ..., "duration": ...}`，对下游流水线零改动**（`end-1` 只消费路径）。
2. 新增模板目录 `backend/service/codetpl/hf/`（HTML/CSS 版），或按风格 `codetpl/<style>-hf/`。
3. `nodespec.go` + `nodecatalog.go`：若把 `backend` 暴露成字段，**必须同时改这两处**（AGENTS.md：两表键集合不一致，`nodecatalog_test.go` 立刻红）。
4. `data/pipelines.json` 的 `knowledge_film`：给 `backend` 加字段时**必须带 `bind`**（**没有 `bind` 的参数会被 API 接受却永不落到节点 data**——AGENTS.md 记录过这个静默坑）；**更省事：不暴露给用户，由 `style` 直接决定后端**。

**收益**：排版从「Canvas 2D 手绘坐标」升级到 **HTML/CSS**（表格、网格、可变字体、真正的盒模型），直接对标简报里的「dark-card-world / 三色纪律 / 卡面组件库」；**不再依赖 `D:/AI/lemo-opuscar` 这个本机绝对路径 + 官方不支持 Windows 的第三方库**；`--batch` **天然对应** FE 的「一卡一镜」；`check`/`lint`/`benchmark` 可直接当门；仍是**纯 CPU**、不调生成模型、不动显存仲裁 → **`queue.go` 的 `cpuOnlyNodeTypes` 白名单无需改**（`code_video` 已在其中）。

**风险**：**Node ≥ 22** 硬要求（lemo 是 ≥20），`FLOWEDGE_NODE` 需指向 22+；引入**远大于 lemo** 的 npm 依赖树（部署体积与升级面变大，需评估是否 vendor）；`HeadlessExperimental.beginFrame` 依赖 Chrome 版本行为（**本轮未验证**，HyperFrames 提供 `--docker` / `doctor` 兜底）；4 个 Canvas 模板**不能复用**，每种都要重写 HTML 版。

**落地顺序**：先只做**一种**风格（`darkcard-hf`）→ 与现有 `darkcard` 做**同 spec A/B**（帧数、墙钟、抽帧目视）→ 过 `verify-media.py` 再决定推广。

### 3.4 最短路径：新增「一种视觉风格模板」（已核实为 4 处改动）

> 简报说的 `dark-card-world` **已在跑**（`darkcard`）。下面是「再加第 5 种」的**精确配方**，已逐行核对源码。
