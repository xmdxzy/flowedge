# 出片流程与显存路线

> 2026-10-25 落地。回答两个问题：**一条片子要过哪些门**、**一张 24G 卡上模型怎么排班**。
> 改动点：`shotlist` 装配后处理 + 终检门、plan 复审补强、`data/model_residency.json`、换侧等待。

## 一、结论先行

- 质量链从「预检 + 段级门」扩到 **预检 → 逐镜门 → 装配 → 音画对齐 → 响度归一 → 终检门**，终检 FAIL 直接进 `gate_verdict`，不再只写日志。
- 音画漂移从「靠外面脚本抓」变成 **装配时修根因**（按视频流时长重封音轨），修完再验。
- 显存排班从「代码里写死的五条过期模型」变成 **一张表**（`data/model_residency.json`），启动时登记并打一行可读路线；换侧两个方向都等显存真归还。

## 二、质量链（按执行顺序）

| # | 门 | 位置 | 判据 | 失败行为 |
|---|---|---|---|---|
| 1 | 分镜复审 | `consistency_plan.go` | 轴线/光比（continue 才判）、场景锁字节全等、**angle 多为景别**、运镜单调、特写接特写 | FAIL 不开机；单调/重复只 WARN |
| 2 | 五层门预检 | `filmgates.go` | 分镜表声明 vs `gates`（技术/音频/身份/时长/预算） | FAIL 不开机 |
| 3 | 逐镜生成门 | `shotlist.go` 循环内 | 台词段 ASR 验词；氛围段中置相消 + 人声抽检 | 按 `segment_retry` 重拍该镜 |
| 3.5 | **单镜验收 + 定点重拍** | `clip_accept.go` | 有音轨、帧数 ≥ 计划 95%、单镜音画差 ≤0.2s | 只重拍坏的那一镜（`reshoot_max` 轮，默认 1），好镜不动 |
| 4 | 装配 | `assembleShots` | cut=1 帧 / continue=2 帧 / dissolve=0.3s | 报错 |
| 5 | **音画对齐** | `avsync.go` | 音轨与视频流时长差 >0.05s 就重封（apad + `-t` 视频时长，视频流 copy） | 重封失败降级 WARN，不交坏件 |
| 6 | **响度归一** | `audio_master.go` | `loudnorm I=lufs TP=-1.5 LRA=11`，默认 -16 LUFS | 失败降级 WARN |
| 7 | **BGM 混音**（可选） | `audio_master.go` | 给了 `bgm` 才跑；`bgm_gain` 默认 -18dB；`bgm_duck` 用原音轨做旁链 | 文件缺失 WARN |
| 8 | 成片自检 | `inspectMedia` | 帧数 + 音画时长 | 写 `check`/`check_ok` |
| 9 | **终检门** | `film_final_gate.go` + `runGateChecks` | 视频流/音频流存在、分辨率下限、帧数 ≥ 各镜总帧 90%、时长、`av_drift ≤ 0.2s`、响度上下限、静音缺口 | FAIL 进 `gate_verdict`，调用方按门决策 |
| 10 | 色度漂移 | `consistency_color.go` | 相邻镜 U/V 均值差 >6 | WARN `plan.color_shift` |

**关键取舍**：5/6/7 都只重编码音轨（`-c:v copy`），不产生视频代际损失，单次耗时约 1–5s。
**顺序不可换**：先对齐再归一，否则响度链以错误时长工作；BGM 最后混，避免被归一二次压低。

## 三、显存路线（单卡 24G）

### 侧别与模型

| 侧别 | 模型 | 实测峰值 | 冷加载 | 说明 |
|---|---|---|---|---|
| diffusion | minimax_h3 | ~20GB | 180s | 8189 独立工作树；与主实例/MOSS 互斥 |
| diffusion | flux1-schnell-fp8 | ~17GB | 183s | 8188 主实例；热生成只要 3s |
| diffusion | moss_image | ~12GB | 120s | 8190；与 H3 互斥 |
| language | qwen2.5:14b | ~9GB | 30s | 分镜/提示词/文案 |
| language | dsh-lens-8b | ~6.2GB | 25s | 视觉理解 |
| language | qwen3-vl:2b | ~2GB | 10s | 轻量 VLM |
| audio | whisper-large-v3 | ~3GB | 20s | 台词验词 |
| audio | audio8-tts-0.6b | ~2.4GB | 40s | 念唱音轨（默认 CPU 服务，不占显存） |

表在 `data/model_residency.json`（运行时是 `运行/data/model_residency.json`）。改模型 = 改表，不改代码。
引擎启动日志会打一行：`[residency] 已登记 N 个模型（总显存 …）：diffusion：… ｜ language：… ｜ audio：…`

### 一条 film 的时间线

1. **language**：`storyboard` 规划（LLM，CPU/显存 ~9GB）→ 审 plan。此阶段 diffusion 可以不在。
2. **换侧 → diffusion**：`enterSide(sideDiffusion)` 先 `UnloadAllLoaded()` 卸载语言侧，**再等 12s / 16GB 真归还**（`waitVRAMFree`），然后进 H3。
3. **diffusion 常驻**：逐镜生成。整段 `shotlist` 都在 diffusion 侧，不会中途来回切。
4. **装配 + 后期**：纯 CPU（ffmpeg），不占显存。此时可以把 H3 留在显存里等重拍。
5. **audio**（按需）：台词镜 TTS 念稿在 `sideAudio`；若 TTS 走 CPU 服务则不触发换侧。

### 切换规则

- `heavyMu` 串行化所有重任务：并行节点不会同时抢显存。
- 换侧才卸载；同侧连续调用不重复卸载。
- **两个方向都等归还**：
  - 进语言侧：`releaseDiffusionAndWait()`（最多 12s，等 free >16GB）
  - 进扩散侧：`waitVRAMFree(16000, 12s)`（2026-10-25 新增，之前只调用 `UnloadAllLoaded()` 就走）
- 共存判断：`canCoexistWithLanguage` 只在「拿得到模型体积 + 拿得到真实 free」时才允许不卸载，否则保守卸载（宁可多花 180s，不可 OOM）。

## 四、怎么改

- **换模型 / 加模型**：改 `运行/data/model_residency.json`，重启引擎。
- **调门限**：改 `gates.technical` / `gates.audio`（plan 里），终检门会自动继承（`filmFinalRules` 从同一份 gates 取阈值）。
- **开关后期**：`film` / `film_from_plan` 流水线字段 `audio_master` / `lufs` / `bgm` / `bgm_gain` / `bgm_duck` / `interp`。
- **开关重拍**：`reshoot_max`（0=不重拍，1=默认，3=最狠）。修复轮**不查预算**——门已经判不过时，停下等于交坏片。
- **看结论**：节点输出 `gate_verdict`（OK/WARN/FAIL）、`final_check`（逐项终检）、`post`（后期做了什么）、`reshoots`（重拍了几镜）。

## 五、已知限制（未验证项别当成已验证）

- 终检门的 `forbid_speech` 用的是能量法，不是 ASR；要 ASR 级判读仍是逐镜门那层。
- **定点重拍只按客观三项判**（音轨/帧数/音画差）：画面塌了、人物变形这类观感问题它看不出来，仍要靠抽帧人工/VLM。
- 重拍一镜会重新消耗一次该镜的生成时间（3.3 分钟级）；重拍的镜若是 `continue` 衔接，下游那镜的引导帧仍是旧的（需要连带重拍时把两镜都标坏，目前不做级联）。
- BGM 只支持单文件铺底，没有段落化/节拍对齐。
- 插帧（`interp`）是 CPU `minterpolate`，大动作会糊。
- 显存峰值来自实测日志，不是实时读表；`waitVRAMFree` 依赖 `nvidia-smi`。
