# WorkBuddy Harness Token 优化（2026-10-23，三轮）

> 口径：**先量化再动手**。所有数字来自脚本字符统计（`len(open(...).read())`），不是估算。
> 复核命令：`python scripts/token-audit.py`（静态）/ `--session`（会话内）/ `--dup`（跨文件重合）。

## 0. 结论

**8 份每会话注入的文件：58,072 → 25,643 字符（−55.8%），约 41.8k → 18.5k tokens，每会话固定省 ≈23.3k。**

不靠关功能、不靠删规则，靠三件事：**把「查得到」的搬去按需读**、**把三份副本合成一个 owner**、**把散文压成语义不变的表**。

**第三轮的关键结论（原计划外的发现）**：静态注入已经不是主要成本。同一会话实测**自动压缩摘要 142,147 字符 ≈102k tokens，是静态注入的 5.8 倍**；摘要由 transcript 生成，transcript 主要由工具输出决定 ⇒ **继续砍文件只能动 3% 的账，控制单次输出才是主账**。已把规则写进 `AGENTS.md §0.14`，并把测量固化成脚本。

## 2. 根因（两条，都不是「文件太长」）

**① 同一批铁律有三份副本，其中两份每会话都注入。**
`~/.workbuddy/MEMORY.md`（§一 铁律 1–10 散文）、用户级 `MEMORY.md`（铁律速查表）、`takeover/RULES.md`（索引）讲的是同一件事。三处措辞不同，所以**14 字窗口的文本重合度检测只有 1.3%**——必须按语义判定，不能靠 diff 找。现按「一个事实一个 owner」：**表在用户级 MEMORY，散文副本已删，`RULES.md` 只做索引**。

**② 项目 `AGENTS.md` 一个文件占 69%，其中 73% 是实现记录不是作业纪律。**
按「不知道这条会不会让我做错事」二分：会 → 留主文件；只是查得到更好 → 迁实现档案 / 技能 `references/`。

## 5. 防反弹（关键，否则三个月后又涨回去）

**新记录二分法**：写之前问一句「不知道这条会不会让我做错事」——
- **会** → `AGENTS.md` §0（判断纪律）/ §6（别再投入）；
- **只是查得到更好** → `docs/AGENTS-实现档案.md`（按 §编号 grep 单节）或 skill `references/`。

**体量红线**（第三轮按事实量级校准）：`AGENTS.md` ≤ 10k 字符、项目 `MEMORY.md` ≤ 6k（多会话共写，±5% 容差）、全局 `MEMORY.md` ≤ 2.5k、用户 `MEMORY.md` ≤ 4k。超线先删叙述，不许删规则；**状态快照不进注入文件**（进 `INDEX.md`）。

**规则不写两份**：一条规则只在一个文件里有正文，其余写「见 X」。指针可以多，副本只能有一份。

## 6. 行为层（同样吃 token，靠习惯不靠配置）

- 读文件先 `Grep` 或带 `offset/limit`，禁整读 >30KB；`99-归档/`、`_history/` 默认不读。
- 同类侦察合成一条命令，一次往返拿全量。
- 代码/配置没变时不复跑回归。
- 汇报表格化、结论先行，不把过程复述一遍。

## 7. 未验证与风险

- **不是 API usage**：数字是字符统计折算（×0.72）。要精确对应在下一轮会话开头读一次真实 usage。
- **并行会话会覆盖基线**：本轮项目 `MEMORY.md` 在测量期间被另一个会话写了约 800 字符，导致该项显示 +10%。同一文件双写有冲突风险——**改 memory 前先看 mtime**。
- **档案/技能命中率未知**：`environment.md` 与实现档案若被频繁回查，回查成本可能吃掉收益。判据：同一节每天查 ≥3 次就搬回主文件。

## 9. 第三轮：静态到顶，钱在 transcript（2026-10-23 午后）

### 9.1 量化：静态只是首付

| 项 | 字符 | ≈tokens | 相对静态 |
|---|---:|---:|---:|
| 8 份注入文件（可控） | 25,643 | 18.5k | 1.0× |
| **同会话自动压缩摘要（2 篇）** | **142,147** | **102.3k** | **5.8×** |
| 单条 >4KB 的工具输出 | 45 条 | — | 含整读 `AGENTS.md` 13,236 / `MEMORY.md` 11,065 / 画布评估 9,839 |

摘要不是我能配置的（`app-config.json` / `settings.json` 里没有 compression 相关键），但它**由 transcript 生成**：transcript 里每 1KB 噪声，压缩后仍会长进摘要里。所以控制点在**生成侧**，不在摘要侧。

### 9.2 harness 侧目录：上界 87k，实际只注入子集（不动的理由）

| 目录 | 缓存全量 | 本会话实际注入 | 若关闭能省 |

**判断：不动。** 3.8k 字符换掉两条真实能力，与第二轮结论一致；且 `browser`（2,251 / 32 工具）是铁律要求的自动化安全通道，关掉会推人去动用户浏览器。

### 9.3 本轮动作

1. **`scripts/token-audit.py`**（新，三个口径）：`--session` 报压缩摘要与单条大输出、`--dup` 报跨文件 14 字窗口重合、默认报静态注入与红线。**替代本轮 8 次临时探针（≈20KB transcript）**；以后审计一条命令、输出 <1KB。
2. **`AGENTS.md §0.14 上下文预算`**（≈300 字符）：单条输出 ≤2KB、>4KB 文件禁整读、一次性测量先查 `scripts/`。这是本轮唯一**增加**静态却划算的投入。
3. **状态快照移出注入文件**：`MEMORY.md` 里「10/15 条工作流有门 / wf3 为何撤回」属会过期的快照，迁 `INDEX.md §C`，注入文件只留规则 + 指针。
4. **红线校准**：项目 `MEMORY.md` 5k → 6k（±5% 容差）。原因写实：它是多会话共写文件，字符级硬删会伤事实，报警交给脚本。
