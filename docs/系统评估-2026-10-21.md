# FlowEdge 系统级结构评估 + 竞品二维能力图

日期 2026-10-21 · 口径：**私有化 · 单卡 · 本地多模态工作流**
方法：只读实测（代码统计 + 依赖方向扫描 + 关键文件精读），不改代码、不启模型、不动 8080 实例。

---

## 0. 五条结论

1. **分层是干净的**：`service → model`、`handler → service` 单向，反向引用为零，无循环依赖。
   问题不是"写得乱"，而是**节点元数据没有单一来源** —— 加一个节点的边际成本是 9–14 处改动。
2. **后端测试在同类上游**：317 个 `Test*`、9,372 行测试对 18,450 行 service（51%）；
   **前端 9,666 行零测试**，是全项目最薄的一环，改 UI 只能靠手点。
3. **二维图上 FlowEdge 站住"单卡深度区"，但广度只有 4.3**（4.3 / 7.7）。
   右上"双高区"（X≥7 且 Y≥6.5）**目前没有产品站住**。
4. **与 ComfyUI 的差距不在生成本身，在生态厚度**；FlowEdge 的优势几乎全部落在
   "ComfyUI 结构上管不到的地方" —— 跨进程、成片验收、成本预测。
5. **广度只能借不能造**：四条接入点（OpenAI 兼容 / MCP / ComfyUI API 格式导入 / 运行期插件）
   已全部就位，现在缺的不是接口，是**可被别人复用的资产**（模板、示例、release）。

## 2. 结构上做对的六件事

| # | 事实 | 为什么值钱 |
|---|---|---|
| 1 | 分层单向、无环 | 改动可局部推理；service 可脱离 HTTP 单测 |
| 2 | 执行侧已插件化（registry map） | 加节点不用改引擎主循环，插件可运行期加载（`data/plugins/`） |
| 3 | 依赖注入统一走 `SetXxx` | 测试可替换 LLM/ComfyUI/显存/事件，316 个测试能零 GPU 跑 |
| 4 | 错误码稳定（`classifyError` → `timeout/config_missing/cycle/retry_exhausted/cancelled`） | UI 与告警不必解析字符串 |
| 5 | 能力与依赖集中（`capabilities.go` + `preflight.go` + `Degraded` 语义） | "没起"与"跑着但坏"分开，不会拿重启去修缺包 |
| 6 | 验收工具独立成脚本（`scripts/film-gates.py` / `verify-media.py`） | 质量门可脱离引擎在 CI 里跑，退出码即门禁 |

### S1 的修法（唯一值得先做的一条）

```go
type NodeSpec struct {
    Type      string
    Side      string            // diffusion / language / speech / none
    Heavy     bool
    Timeout   func(*model.NodeInstance) time.Duration
    Validate  func(*model.NodeInstance, map[string]bool) []Issue
    Deps      func(*model.NodeInstance) []DepRequirement
    Lineage   bool
    Params    []ParamDef        // 同时可下发前端，替代手写属性面板
}
var NodeSpecs = map[string]NodeSpec{ ... }   // 27 条，一个文件
```

用一张表替掉 6 处 switch + 血缘白名单，顺带让 `GET /api/capabilities` 能带参数 schema
（前端属性面板就能从"手写"变成"渲染"）。**这是唯一能同时降低后端与前端加节点成本的改动。**

## 4. 二维能力图：口径

### 4.1 两轴与子项权重

**X 轴 = 编排与生态广度**（能接入多少、能复用多少、能被谁集成）
`0.4 × 节点/连接器数量` + `0.3 × 外部资产复用` + `0.3 × 标准协议兼容`

**Y 轴 = 单卡本地工程深度**（在你自己那张卡上，能不能稳定、可复现、可验收地出片）
`0.30 × 显存治理` + `0.25 × 多模态闭环` + `0.25 × 质量与一致性` + `0.20 × 可复现与可观测`

> **口径声明**：Y 轴衡量的是**工程化闭环**，不衡量"模型/采样器丰富度"。
> ComfyUI 在生成原语丰富度上领先（决定画面质量上限），这一点不在 Y 轴里体现。
> 这也是为什么 ComfyUI 只有 6.0 —— 不是它弱，而是本轴只问"工程收口"。

### 4.2 评分表

| 产品 | X 子项（节点 / 资产 / 协议） | X | Y 子项（显存 / 多模态 / 质量 / 复现） | Y |
|---|---|---:|---|---:|
| **FlowEdge** | 4.0 / 3.0 / 6.0 | **4.3** | 8.5 / 7.0 / 8.5 / 6.5 | **7.7** |
| **ComfyUI** | 10 / 9.5 / 8.0 | **9.3** | 7.0 / 7.5 / 4.0 / 5.0 | **6.0** |
| **n8n** | 10 / 9.0 / 7.0 | **8.8** | 0 / 1.0 / 1.5 / 3.0 | **1.2** |
| **Coze 扣子** | 8.0 / 7.0 / 6.0 | **7.5** | 0 / 2.5 / 1.5 / 2.0 | **1.8** |
| **Dify** | 6.0 / 5.5 / 8.0 | **6.4** | 0 / 1.5 / 1.5 / 3.5 | **1.5** |
| **即梦 / 可灵** | 3.0 / 3.0 / 2.0 | **2.6** | 0 / 4.0 / 3.0 / 1.5 | **2.2** |

> LangFlow（5.0 / 0.6）与 Open WebUI（3.6 / 1.8）与 Dify 区域重叠，图上不单独标注。

**分数依据（关键几条）**

- FlowEdge **显存 8.5**：跨进程三类仲裁（ComfyUI / Ollama / ASR-TTS）、`canCoexistWithLanguage`
  按真实 `vram_free` 与模型体积判共存、双实例 `exclusive` 互斥组、重节点自动采峰值写档案。
  扣分：真实卸载次数的前后对照**未实测**（ComfyUI/Ollama 当时均停），只有单卡单机场景。
- FlowEdge **多模态 7.0**：文/图/视/音 + 分镜 + 成片全链通；扣分：**字幕 `AddSubtitles` 仍是死代码**
  （`multimodal.go:650` 仅定义、零调用）、无 9:16 竖屏、无 BGM 侧链、无 lip-sync、无视频超分。
- FlowEdge **质量 8.5**：五层门（timing/identity/audio/technical/budget）+ `SCENE LOCK` 字节全等校验
  + `verify-media.py` 四件套 + `select`/`quality_gate` 节点 + 单镜 reroll（已接 UI）。
- FlowEdge **复现 6.5**：trace 有墙钟/token、`/api/estimate` 给区间并标 `extrapolated`；
  扣分：血缘只 3 类（S5）、seed 未全量留痕、估算样本 <3 时降级。
- ComfyUI **显存 7.0**：官方已具备进程内 smart VRAM / 模型 offload / 部分重算；
  但**跨进程为 0** —— 它管不到 Ollama 和 faster-whisper。
- ComfyUI **质量 4.0**：没有质量门、没有自动重抽、没有一致性锁；一致性靠 ControlNet/IPAdapter 手工搭。

### 4.3 读图

| 象限 | 谁在 | 含义 |
|---|---|---|
| 左上 单卡深度区 | **只有 FlowEdge** | 靠"进程之外"的能力排他：跨进程显存、成片验收、成本预测 |
| 右上 双高区（X≥7 且 Y≥6.5） | **空缺** | 生态厚度与工程深度尚未被同一产品同时占住 |
| 右下 广度区 | ComfyUI 9.3/6.0、n8n 8.8/1.2、Coze 7.5/1.8、Dify 6.4/1.5 | 广度可以靠云服务与社区堆，深度不能 |
| 左下 | 即梦/可灵 2.6/2.2 | 画质标杆，但不可离线、不可编排、无显存治理 |

**结论的稳健性**：把双高门槛在 X 6.5–7.5、Y 5.5–7.0 之间任意移动，"无产品同时越过两条线"的结论不变
（唯一接近的是 ComfyUI，它在 X 轴早已越线，Y 轴卡在 6.0）。

## 5. 逐项差异

### 5.1 FlowEdge 能做、图上其他家结构上做不到

| 能力 | 为什么别人做不到 |
|---|---|
| 跨进程显存仲裁（三方抢一张卡） | ComfyUI 的 VRAM 管理止步于自己进程；Ollama 同理。要仲裁必须有一个**进程外的编排层** |
| 双实例语义（8188 主 / 8189 H3，互斥组） | 需要"多实例 + 路由 + 互斥"三件套，ComfyUI 单实例单 venv |
| 提交前显存/耗时区间预测 | 需要历史档案 + 同类型回归 + 显存采样，ComfyUI 无成本概念 |
| 出片验收门（帧数/接缝/响度/ASR/场景锁） | 需要"计划 vs 产物"的对账，节点图本身没有"计划"概念 |
| 镜头级断点与 reroll | ComfyUI 有 partial re-execution（节点级），没有"镜"这个语义层 |

### 5.2 别人能做、FlowEdge 现在做不到

| 缺口 | 现实影响 | 成本 |
|---|---|---|
| 生态资产厚度（模板 9k+ / 节点 5k+ 扩展） | 用户来了没东西可抄，第一步就是空白画布 | 不能自造，只能借（见 §6） |
| 生成原语丰富度（采样器/LoRA/3D/音频链） | 画面质量上限受限于引擎暴露的参数 | 中：可透传给 `comfy_workflow` 缓解 |
| 字幕 / 竖屏 / BGM 侧链 | **短视频交付的准入门槛**，现在缺 | S 每项（`video_edit.go` 加 `buildPostFilters`） |
| 云端一键发布渠道（Coze 那类） | 与离线定位冲突，属战略放弃 | — |
| 多租户 / RBAC | 单机单人，明确放弃 | — |

## 7. 未验证 / 口径风险（单独列，不与已验证混写）

1. **竞品分数是判断，不是测量**。X 轴数量类有外部数据支撑（ComfyUI 生态 5k+ 扩展、n8n 官方 1k+ / 目录 2k+ / 模板 9k+），
   但 Y 轴工程深度是**基于公开文档与本地经验的估分**，没有对每家做同机同任务实测。
2. **ComfyUI star 数来源不一致**：本次检索到 121k / 138.7k / 140.8k 三种口径（同一周内）。
   故本报告不使用 star 数作为评分依据，只用"生态扩展数量级"。
3. **FlowEdge 的 Y 轴分数里有两项是"代码已落地、效果未实测"**：
   真实卸载次数对照、共存策略实际省下的秒数。文档里按"逻辑已验证、收益未实测"计分。
4. **前端像素级布局未验证**：本机浏览器截图通道不可用（`tab_screenshot` 忽略 clip，
   `Add-Type` 被安全策略拦），UI 只验证到"代码打包 + tsc + 组件发的请求真实返回"。
5. **S1 的改动量是估算**：27 个节点 × 6 类元数据，尚未做一次真实迁移试点。
