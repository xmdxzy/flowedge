## 一、结论

| # | 结论 | 证据强度 |
|---|---|---|
| 1 | **引擎能调用外部 CLI 智能体并拿到真实产物**：`agent_task` → `dsh headless` 子进程，exit 0，产物落到指定工作目录 | 强（29/29 真跑通，2 次重复） |

## 二、测试任务（成本：一次 ≈ 2 分钟，纯 CPU，零 GPU）

自造 fixture `tinykit`：3 个 Python 模块 × 2 个缺陷 = 6 个缺陷，29 条 unittest 用例。

- 初始基线：**14 / 29**（13 failures + 2 errors）
- 判分器 `grade.py`：跑全量用例 + 校验 `tests/` 逐文件 sha256 + 扫描 skip/xfail → 输出 `{ok, passed, total, cheated, score}`
- 作弊口径：改测试、加测试文件、加跳过装饰器，任一命中直接 0 分

任务载体选它的理由：**判据完全确定、可重复、可自动验真**，且子任务天然可拆三份。

## 三、图结构（A 组）

```
start-1
  └→ prep-1 (http_request POST /prepare)        建 3 个隔离副本
       ├→ fix-a (agent_task · DSH · work_a)     只许改 pkg/mod_a.py
       ├→ fix-b (agent_task · DSH · work_b)     只许改 pkg/mod_b.py
       └→ fix-c (agent_task · DSH · work_c)     只许改 pkg/mod_c.py
            └── 三路汇聚 → grade-1 (POST /apply-grade)   合并 owned 文件 + 判分
                 └→ gate-1 (if_else contains '"ok": true')
                      ├→ end-ok    (true 分支)
                      └→ end-fail  (false 分支)
```

- 9 节点 / 10 连线 / 6 拓扑层
- 引擎自动生成任务书 `spec?format=md` = **8,172 字节**（执行顺序 + 参数 + 验收门 + 产物清单，可直接交给任何 harness）
- 运行自报评测语义：`invoked_by=workbuddy`、`caseId=tinykit-6bugs`、`role=candidate`、`evalBatch=orch-bench-20261023`、`workflow_version=0`

## 五、引擎实际表现出的能力面

1. **异构扇出**：`agent_task` 按 `data/agents.json` 名册选执行体，命令行不落工作流，密钥由包装脚本从 `~/.dsh/.credentials.yaml` 取（不进图、不进配置）。
2. **确定性与非确定性分离**：agent 节点输出带 `nondeterministic: true`，确定性判分走独立 HTTP 节点，评测时天然可分组统计。
3. **分支裁剪**：`if_else` 走 true 分支后，`end-fail` 状态为 `skipped` 而不是 `failed`，不会污染运行结论。
4. **越界检测**：合并时只取各自 owned 文件，同时把「谁多改了别的文件」逐条报出 —— 6 条 warning 每次稳定复现。
5. **规格即交付物**：`/api/workflows/:id/spec?format=md` 生成 8.2KB 任务书，第三方 harness 不必读画布就能照做。
6. **MCP 对外面**：9 个工具（list_workflows / run_workflow / run_status / estimate / generate_image / get_spec / apply_spec / get_workflow / list_modules），`list_modules` 返回 34 模块 41.5KB。
