# 本地推理服务接入清单（2026-10-23 实战复盘）

> 背景：把 Audio8-TTS 0.6B（PyTorch+CUDA）从「权重下不下来」做到「引擎里能跑、还不常驻占显存」。
> 一天里踩的坑几乎都不是模型问题，全是**接入方式**的问题。下面按「症状 → 根因 → 现在的挡法」记录，
> 下次接 H3 / MOSS / 任何新模型可以直接当检查单用。

## 一、十个坑

| # | 症状 | 根因 | 现在的挡法 |
|--:|---|---|---|
| 1 | 2.45GB 要下 5 小时 | hf-mirror 单连接被限到 140KB/s，16 线程也只有 0.5MB/s | 换 ModelScope `resolve` 直链 → **18.8MB/s（2 分 20 秒）**，快 35 倍 |
| 2 | 每个软件都重下一次 2.4GB torch | 各建各的 venv | 共享底座 `D:/AI/envs/torch-cu124`，torch 系**从 ComfyUI venv 直接复制**，零下载 |
| 3 | 复制过来的环境 import 就炸 | 漏了随包目录：`numpy.libs`(DLL 找不到) / `torio`(torchaudio) / `mpmath`(sympy) | 四样必带项写进 AGENTS §1 |
| 4 | 下载"成功"但文件不在 | `huggingface-cli` 静默失败、退出码仍 0 | 一律 curl + **官方 sha256 逐文件校验**（这次 14/14） |
| 5 | 克隆每次必然超时 | `http.Client.Timeout` 写死 60s，而克隆 RTF 18~32（58 字要 157s） | 超时按工作量估：`60s + 每字 1.5s`，封顶 20min，`context.WithTimeout` 精确控 |
| 6 | 拿到的音色完全不对，节点却报成功 | 服务失败 → 静默回退 Windows SAPI | 克隆请求（`RefAudio != ""`）**禁止回退**，直接报错 |
| 7 | 改了配置没生效 | `autostart` 等字段只在 `NewSupervisor` 读一次 | 新增 `POST /api/deps/reload`，字段级返回变更 |
| 8 | 改环境变量怎么都不生效 | 引擎由外壳 `spawn(exe,[],{detached})` 拉起，**外壳不传 env** | 配置落 `data/deps.json`，优先级 环境变量 > 文件 > 推导 |
| 9 | 跑节点前忘了点启动，产出错音色 | 服务没起就静默降级 | 节点执行前**按需自动拉起** + 等就绪（6 秒） |
| 10 | 用过一次就一直占 1.8GB 显存 | 没人记得点停止 | `idle_unload: 600`，闲置 10 分钟自动把模型卸出显存（进程留着，下次懒加载） |
| 11 | 改配置要重启引擎，且改了没生效也没人知道 | 只读一次的配置项没有 reload 入口 | `POST /api/deps/reload` 返回字段级差异；**比较范围要含 Env**（只比 binary/args 会漏掉注入型配置） |
| 12 | 换 exe 报 `Device or resource busy` | 多个 `FlowEdge.exe --mcp` 瘦客户端常驻占用可执行文件，**不能杀**（是平台的 MCP 连接） | **先 `mv` 旧 exe 改名，再 `cp` 新的**——改名只动目录项，不被句柄锁挡 |

## 二、接入检查单（下次照着走）

1. **权重**：先试 ModelScope（`/models/{o}/{r}/resolve/master/{path}`）；大小与 sha256 以官方清单为准，逐文件核。
2. **运行时**：能不能复用已有 venv？不能就建**共享底座**并把 torch 复制进去，别重新下载。
3. **API 签名**：读官方推理脚本源码，别按自己想象写——这次 `processor(text=[...], reference_audio=[...])` + `model.decode_audio(out.codes)` 都是从 `audio8_tts_infer.py` 抄的。
4. **质量**：ASR 逐字回读原文比对。**"能出声"不等于"能听懂"**（0.1B ONNX 就是能出声、内容是哼鸣）。
5. **性能**：分开报 warmup / 稳态、单句 / batch、有参考 / 无参考；显存报加载峰值而非常驻值。
6. **失败模式**：把超时、降级、静默回退逐条堵死；**宁可报错也不给错结果**。
7. **配置**：能落文件就别只靠环境变量；只读一次的配置项必须有 reload 入口，否则「改了没生效」永远发现不了。
8. **生命周期**：谁起、谁停、空闲怎么办、换侧怎么释放显存。
9. **证据**：看真实产物（`backend` 字段、ASR 回读、ffprobe），**命令返回 0 不算成功**。
10. **回归**：每个坑写一条测试钉住（本次 `tts_clone_test.go` 3 条 + `deps_reload_test.go` 2 条）。

## 三、两条最贵的教训

**静默降级是成本最高的 bug。** 它把"错误"包装成"成功"：音色换了、模型没跑、超时被吞，用户完全看不出来。
凡是"失败了但还能给个东西"的路径，都要问一句：**这个替代品和用户要的东西是一回事吗？** 不是就必须报错。

**"跑通一次"和"能用"之间隔着十个坑。** 跑通只需要一次成功；能用要求在别人手里、在忘了一步的情况下、在显存被别人占着的时候，依然不出错。
