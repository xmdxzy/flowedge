# 音乐生成规则（2026-11-06 定稿）

> 这份文件是「怎么把一首曲子做到能交付」的唯一口径。每条后面都跟着踩过的证据，
> 改动前先读对应小节，别只改结论。

## 0. 最高原则：质量优先，不设固定时长

- **时长是结果，不是约束。** 2 分 45 秒只是《如果回到初见那天》那次的巧合，不是标准。
  结构需要多长就做多长：90 秒能收住就 90 秒，需要 4 分钟铺开就 4 分钟。
- 判据是「结构完整 + 收尾成立 + 不重复啰嗦」，不是「凑够某个秒数」。
- **一次长生成，不拼接。** 见 §6：四段拼接必然在接缝断气，用户原话「只有 1 分钟以后的能听」。

## 1. 生成方式

| 项 | 做法 |
|---|---|
| 方式 | 单次 `POST /release_task`，整曲一次出 |
| 时长 | 按结构定：段落数 × 每段 25–45 秒。165s ≈ 6 段；要更完整就 200–240s |
| 步数 | 纯音乐 24 起步；有旋律细节（钢琴/人声）32–48 |
| 候选 | 一次出 3–4 条，按 §4 门槛挑，不挑「感觉」 |
| 开关 | 纯音乐必须 `use_cot_caption=false` / `use_cot_language=false`（否则卡在 CoT 阶段） |

## 2. 提示词骨架（六段，缺一段就会出问题）

1. **类型 + 调性 + 速度**：`Instrumental cinematic ambient R&B ballad in F# minor at 84 BPM with a half-time feel.`
2. **配器**：具体到乐器与频段（sub-bass / pads / grand piano / brushed drums / hats）
3. **混音空间**：tape saturation、sidechain、wide stereo、reverb
4. **情绪**：intimate and melancholy
5. **禁止项**：`No vocals.`（要器乐就别留口子）
6. **结构**：`intro → verse groove → lifted chorus → stripped bridge → final chorus → fading outro`
   —— 模型对结构列表的服从度明显高于散文式描述（实测：写了结构的几版，段落边界清楚得多）

**配器平衡要写进提示词**：`piano forward in the mix`、`soft brushed drums, not aggressive`。
只写「punchy kick / crisp snare」会把鼓推到 −6dB、钢琴埋到 −21dB（实测，见 §3）。

## 3. 混音平衡：用 demucs 实测，不靠猜

工具：`htdemucs_6s`（能把 piano 单独拆出来）。脚本 `scripts/stem-balance.py`。

**相对全曲电平的合格区间（dB）**：

| 声部 | 合格 | 危险 |
|---|---|---|
| drums | −4 … −6 | 高于 −3 = 节奏过重 |
| bass | −4 … −6 | 低于 −8 = 没有低频支撑 |
| **piano（旋律层）** | **−9 … −12** | **低于 −14 = 听不清** |
| other / pads | −9 … −11 | — |

判据是**钢琴与鼓的差**：超过 10 dB 就必然「听不清」。
实测反例：84bpm 那版 piano −20.8 / drums −5.9（差 **14.9 dB**），用户原话「前面的钢琴太轻了，甚至听不清」。
对照组（用户认可的那首）：旋律层 −13.6 / drums −4.4（差 9.2 dB）。

**修法优先级**：
1. **分轨重混**（`scripts/remix-stems.py`）：piano +10 dB、drums −3 dB，再走母带链。最快，不动作曲。
2. 重新生成时把平衡写进提示词（§2）。

## 4. 客观验收门槛

| 项 | 门槛 | 工具 |
|---|---|---|
| 审美分 CE / PQ | ≥ 参考曲 −0.5 分（0–10 制） | `scripts/song-eval.py`（Meta audiobox-aesthetics） |
| 响度 / 真峰值 | −14 LUFS / ≤ −1.0 dBTP | `scripts/check-song.py` |
| 中段静音缺口 | 0 处 | 同上 |
| 调性 | 全曲主调相关 ≥0.6 | 同上 |
| **频段平衡** | **sub(20–60Hz) ≤ 20%、mid(250–2k) ≥ 22%** | `gen_multi.py` 的 `bands_of` / 本文件 §8 |
| 动态 | 5 秒窗跨度 ≥6 dB，结尾 20 秒内衰减到 −30 dB | 同上 |
| 旋律可辨 | 钢琴 stem 存在且落在 §3 区间 | `scripts/stem-balance.py` |

> 审美分不是万能的：它评「制作质量/内容愉悦度」，评不出旋律是否动人。
> 但它能把「明显做坏了」的候选先筛掉，省下让用户听废片的时间。

## 5. 母带

```
highpass 25Hz(p=2)
lowshelf 75Hz +3.0dB        ← 补低频重量（夹在 +3dB 上限）
equalizer 180Hz −1.5dB      ← 去浑浊
equalizer 800Hz −2.0dB      ← 去中频堆积
equalizer 2500Hz +3.0dB     ← 存在感（钢琴/人声的命门）
highshelf 7000Hz +2.0dB     ← 空气感
两遍 loudnorm（linear）→ −14.0 LUFS / −1.5 dBTP
alimiter 0.85（level=false）
```

与参考曲对比：**2–8kHz 差超过 4 dB 必须补**，否则钢琴 solo 会被合成垫盖住
（实测那版 2kHz 比参考暗 6.4dB，补 3dB 后差 4.1dB）。

## 6. 已验证无效的做法（别再试）

| 做法 | 结果 |
|---|---|
| 四段分别生成 + 2 秒交叉淡化拼接 | 接缝处断气，前半段没有律动，「只有 1 分钟后能听」 |
| 让模型写稀疏独奏钢琴（裸钢琴） | 左右声道被生成成两份不同演奏（L/R 相关 0.02~−0.41），43% 的帧有半音相撞 |
| 期待模型自己写终止式 | 三次实测全部跑调：keyfit 0.00 / −0.35 / 0.02，尾和弦落在 A、B 上 |
| 用 `tempo` 相关推 BPM 倍频 | 152 vs 76 只差 0.04 相关，光看数字会判错，要结合低音/鼓型 |

## 8. 实测记录（2026-11-06，一轮完整迭代）

| 版本 | 时长 | 鼓 | 钢琴 | 鼓−钢琴 | CE | PQ | 用户反馈 |
|---|---|---|---|---|---|---|---|
| 84bpm 初版 | 165s | −5.9 | **−20.8** | **14.9** | 7.44 | 7.83 | 「节奏太重、钢琴听不清」 |
| 同曲 +10dB 钢琴 / −3dB 鼓 | 165s | −8.9 | −10.5 | 1.6 | 7.50 | 7.89 | — |
| v3 提示词（piano forward）c1 | 200s | −3.1 | **−37.6** | 34.5 | — | — | 模型完全没给钢琴 |
| v3 c2 原样 | 200s | −2.9 | −15.2 | 12.3 | — | — | 鼓仍偏重 |
| **v3 c2 重混（+4/−2）** | 200s | **−4.6** | **−8.5** | **3.9** | **7.61** | 7.70 | 交付 |
| 参考曲《如果回到初见那天》 | 165s | −4.4 | —（旋律 13.6） | — | 7.49 | 7.91 | 用户认可 |

三条结论：

1. **提示词写 `piano forward in the mix` 没用**：同一批 4 条里钢琴电平从 −12.7 到 −37.6 乱飘，
   模型根本不按混音指令分配声部。**平衡必须靠分轨重混，不能靠提示词。**
2. **audiobox-aesthetics 评不出「钢琴被埋」**：初版（钢琴 −20.8）CE 7.44，重混后 7.61，
   只差 0.17 分；它评的是制作质量与内容愉悦度，不是混音平衡。两者必须配合使用。
3. **重混能同时抬质量分**：+10/−3 那次 CE 从 7.44 → 7.50、PQ 7.83 → 7.89，说明「钢琴听得清」
   本身就会被判为更好的内容。

## 9. 事故复盘：选段漏了「频段闸门」（2026-11-06）

用户对 c2fix 版的反馈是「节奏不错，但钢琴像在打架、开头不抓耳」。我据此重出一批并按
「动态跨度 + 钢琴半音相撞率」挑了一条（c1），把钢琴 +7 dB 抬上去，结果用户评价
**「更乱而且更难听，还不如上一版」**。

事后测量才看清：

| 指标 | 上一版 c2fix（用户说较好） | 这一版 c1v2（用户说更乱） |
|---|---|---|
| **20–60Hz 能量占比** | **11.7%** | **46.5%**（源头 c1 本身就有 37.9%） |
| 250–2kHz 占比 | 31.4% | 16.5% |
| 频谱质心 | 304 Hz | 192 Hz |
| 起音密度 | 2.91/s | 2.79/s（几乎一样） |

**结论：听感「乱」不是音符变多（起音密度没变），而是低频占比翻了 4 倍、中频被吃掉一半。**
根因有二：
1. 选段标准里只有动态与钢琴指标，**没有频段平衡**——c1 一出生就是低频糊的，我却按「跨度大」选了它；
2. 在基础上又给钢琴 **+7 dB**，把中频稍微抬起来的同时也抬了它自身的低频，越救越糊。

**已修的**：`gen_multi.py` 增加 `bands_of()` 与硬门槛（sub ≤20%、mid ≥22%），不达标的候选直接淘汰；
本文件 §4 增加频段行。

**试过但无效的**：给钢琴 stem 先高通 180Hz 再抬 +4dB → 低频占比反而从 11.7% 升到 33.7%
（钢琴被滤掉低频后整体变轻，鼓与贝斯的低频占比相对上升）。**EQ 救不了「钢琴写得乱」，只能换音色或换候选。**

## 10. 分轨目录必须显式列名，禁用 glob（2026-11-06，同一天踩的第二坑）

`htdemucs_6s/` 下同时存在 `c2_*.wav`、`c2_master_*.wav`、`c2fix_master_*.wav` 三套分轨
（分别来自同一个候选、它的母带、母带的母带）。用 `c2_*.wav` 这种 glob 会**同时命中三套**，
按「最后一段下划线取 stem 名」的写法互相覆盖 —— 结果是每次求和的「鼓」来自 A 套、「钢琴」来自 B 套。

症状很有欺骗性：同样的增益参数，两次求和出来的频段占比差 20 个百分点，
而我一度以为是母带链或量化的问题。**教训：分轨一律按 `前缀_声部.wav` 显式列六个文件名。**

## 11. 开头抓人的做法（已验证）

在**成品母带**上做（不要重混分轨）：

```
volume='min(1.45,max(1,1.45-(t-38)/12*0.45))':eval=frame   # 0–38s +3.2dB，38–50s 回落
equalizer=f=800:t=q:w=1.2:g=2.5:enable='lt(t,48)'          # 钢琴琴体
equalizer=f=2600:t=q:w=1.0:g=1.5:enable='lt(t,48)'         # 钢琴存在感
```

实测效果：开头 20 秒从「比主体低 1.8dB」变成「比主体高 0.3dB」，而全曲频段几乎不动
（sub 11.7%→11.6%、mid 31.4%→32.0%）。**在成品上做自动化，比抬分轨安全得多**——
抬分轨会连带改变整个频谱平衡（见 §9）。
