## 0. 一页结论：FE 应该抄的 12 条机制

按"投入产出比 × 与 FE 现有短板的对齐度"排序。每条只写一句能落地的话，细节在 §1 机制表。

| # | 机制 | 来源项目 | 一句话落地 |
|---|---|---|---|
| 1 | **缓存严格度分级**（`false` / `true` 元数据 / `'deep'` 内容哈希 / `'lenient'` 只比名+大小） | Nextflow `cache` directive | 不做"开/关"二选一，把缓存严格度做成图级字段，默认 `true`（比尺寸+mtime），关键节点显式 `deep` |
| 2 | **缓存命中后二次校验产物存在性 + 退出码** | Nextflow `-resume` 语义 | 命中缓存不等于可用：还要核产物文件在、大小对、上次 exit code 有效，否则重算 |
| 3 | **缓存键 = 输入值 + 节点实现版本 + 运行域指纹** 三元组 | Prefect `cache key` = inputs + task source + flow run id | FE 现在缺"节点实现版本"这一维，导致改代码后旧产物仍被当命中 |
| 4 | **显式失效声明位**（节点自己说"我的输出是否受某外部量影响"） | ComfyUI `IS_CHANGED` + `UNIQUE_ID` hidden input | 把"这个节点依赖外部状态"写成节点元数据字段，而不是靠猜输入 |
| 5 | **非确定性输入必须显式注入 nonce** | ComfyUI 节点级输出缓存（AGENTS 已踩） | 重跑/AB 时强制挪 seed 与 prompt 尾注；把"假重跑"变成编译期拦不住的运行期断言 |
| 6 | **重试四元组**：`limit` + `retryPolicy`（按失败类型）+ `expression`（按上次结局否决）+ `backoff` | Argo Workflows `retryStrategy` | 重试策略从"次数+固定超时"升级成"可重试性分类 + 按上次 exitCode/时长否决" |
| 7 | **业务代码可主动否决重试** | Dagster `Failure(allow_retries=False)` / `RetryRequested` | 台词念错、身份漂移这类"重试无意义"的失败要能一键判死，不浪费 6 分钟一镜 |
| 8 | **心跳超时把"卡住"和"死了"分开** | Temporal `heartbeat_timeout` + heartbeat payload | ComfyUI 长任务应该发"进度心跳"，超时按"多久没新进度"算，不是按总时长 |
| 9 | **节点级三选一错误策略 + `error_type` / `error_message` 变量** | Dify 错误处理 | 每个节点的失败策略三选一：重试 / 用默认值续跑 / 走失败分支；下游能读到错误类型 |
| 10 | **人工介入 = suspend + resume URL + 审批计数** | Windmill `getResumeUrls()` | 质量门控需要"人看一眼再继续"时，用一条可点链接恢复，而不是占着一个 worker 空转 |
| 11 | **局部执行**（选中输出节点，只跑它的上游分支） | ComfyUI Partial Execution | 画布最大的省钱开关：改一个后处理节点不该把 20 分钟生成重烧 |
| 12 | **产物与画布同源**（结果直接落回图层/暂存区，带参数快照） | InvokeAI staging area / Krita layer=region+prompt | 资产复用的短板不在存储，在"产物没有回到图里"；落盘时同时写节点 id + 参数快照 |

> 补充三条"顺手就能抄、成本 S"的：Snakemake 的**按文件名连边**（输入输出文件名相同即自动连依赖）、DVC 的 **`dvc.lock` 记录 md5 + params**、ComfyUI-Manager 的 **`security_level` / `network_mode` 双闸门**。

## 2. 反例：对"单机 Windows + 24GB"是陷阱的方案

判据只有一条：**它解决的问题，在 FE 的真实瓶颈上是否存在**。FE 的瓶颈实测是显存（H3 权重 20.5GB / 峰值 23.8GB）、盘读（每镜 35.4GB / 113s）、页文件（峰值 27GB），不是调度吞吐。

| # | 陷阱 | 为什么在 FE 上是陷阱 | 该怎么替代 |
|---|---|---|---|
| 1 | **整套上 Temporal / Argo / Nextflow** | 三者都要额外运行时（Temporal 要服务端+DB；Argo 要 K8s + CRD + ConfigMap；Nextflow 要 JVM + LevelDB 会话缓存）。FE 是 Go 单 exe，加一个 Postgres 就为了"重试策略"是负收益。Argo 的 memoization 还受 **ConfigMap 1MB** 限制。 | **抄字段不抄运行时**：把 `limit / retryPolicy / expression / backoff` 四个字段照抄进 `deps.json` 或节点元数据，用 Go 里 100 行实现。 |
| 2 | **全局开 Nextflow `cache 'deep'`（内容哈希）** | deep 要把输入文件**整个读一遍**算哈希。FE 的盘已经被权重读取打到 313MB/s（盘本身 2.6GB/s），一镜产物几百 MB，deep 化等于把出片时间再加一截，而命中率仍低（抽卡本就该重抽）。 | 严格度分级（§1.3 Nextflow 行）：默认 `true`（尺寸+mtime），只对**参考图/字幕/超分**这类纯函数节点开 `deep`。 |

## 3. 三条跨项目洞察

### 洞察一：缓存键的真正分歧不是"哈希什么"，而是"谁有权声明失效"

四个项目把"失效声明权"放在了四个不同位置：

- **ComfyUI**：给**节点作者**——`IS_CHANGED` 由节点自己实现，`UNIQUE_ID` 通过 `INPUT_TYPES()["hidden"]` 声明（源码里 `include_unique_id_in_input()` 检查 `"UNIQUE_ID" in class_def.INPUT_TYPES().get("hidden", {}).values()`）。节点最懂自己依赖什么外部状态。
- **Nextflow**：给**流程作者**——`cache` 指令四档严格度，是"我愿意为查得准付多少 I/O"的显式交易。
- **Prefect**：给**调用者**——`cache_key_fn` / `cache_policy` / `cache_expiration` / cache isolation，同一份代码在不同运行域里默认不共享。
- **Snakemake**：给**用户**——`--rerun-triggers` 五个勾（code/input/mtime/params/software-env），运行时决定。

FE 的处境是：**四个位置一个都没有**。节点元数据里没有"失效声明"字段，图里没有严格度，调用方没有 key 函数，运行时没有触发器勾选。所以唯一能做的选择就是"全关"——这不是判断失误，是**缺少声明位导致的必然结果**。

> 可执行的判断：先加**一个**字段（节点元数据里的 `cache_invalidators`），就足以让默认打开缓存变得安全。字段内容就是 Snakemake 的五个维度的一个子集。这也解释了为什么"删缓存"是对的临时处置，但不应是终局。

### 洞察二：长任务编排的分水岭是"失败语义分类"，不是"重试次数"

看四个项目各自把"要不要再试一次"的决策权交给了谁：

- **Temporal**：**按层**分类。Workflow 默认不重试（要 deterministic replay），Activity 默认重试（"failure-prone or non-deterministic operations (API calls, LLM invocations, etc.)"）。→ 决策权交给"这段代码在架构里的位置"。
- **Argo**：**按失败类型 + 上次结局**分类。`retryPolicy` ∈ Always/OnFailure/OnError/OnTransientError，`expression` 读 `lastRetry.exitCode / status / duration / message`，且**每次尝试后重新求值**。→ 决策权交给"这次具体怎么挂的"。
- **Dagster**：**按业务语义**分类。`Failure(allow_retries=False)` 由代码自己否决，`RetryRequested` 由代码自己要求。→ 决策权交给"写这段代码的人"。
- **Windmill / Dify**：**按节点**分类。Dify 的 重试 / 默认值 / 失败分支 三选一，是唯一把"**要不要降级继续**"和"要不要重试"分开建模的。→ 决策权交给"这张图的作者"。

FE 现在只有一个分类轴：**超时**。于是"显存被别人抢了"（该重试）、"台词念错一个字"（该重拍这一镜）、"锁句不全"（该让人改提示词）、"引擎 502"（该等 30 秒再试）这四件事走进了同一个分支。AGENTS 里那一串返工——"单节点固定 180s 超时误杀长任务"、"`/interrupt` 对排队提交一个像素都不停"、"tts 超时吃 defaultNodeTimeout 与冷加载打平必然失败"——全是同一个根因的不同表现。

> 可执行的判断：**把分类轴换成二维**——`可重试性`（可重试 / 不可重试 / 需换参数）× `是否需要人`（自动 / 停下等人）。六个格子，每格一个默认动作。这个二维表比任何框架都便宜，且能直接映射到 Argo 的 `retryPolicy` 与 Dagster 的 `allow_retries`。

### 洞察三："统一画布"的三个项目都不是画布更强，而是**产物与画布同源**

- **InvokeAI**：跑完的结果"stream into the **staging area**"，当前图层自动作为输入 → 产物落回画布。
- **Krita AI Diffusion**：**Region = layer + prompt** → 图层的组织方式就是提示词的组织方式，编辑即重生成参数。
- **ComfyUI Subgraph**：折叠即复用单元 → 复用发生在**同一张图里**，不是复制到另一个模板文件。

三者共同的形态是：**产物不是"输出"，是"图的下一轮输入"**。而 FE 现在的产物是终点——跑完落盘，`runs` 表里一行，前端列个列表。用户要复用只能"再跑一遍"。

这也解释了 FE 的"资产复用"短板的真实位置：**不在存储层，在回流路径**。`shot-cache` 已经按内容哈希存了，但它只服务"自动命中"，不服务"用户主动复用"——用户看不见它、选不了它、改不了它的参数。

> 可执行的判断（成本 S，收益最大）：产物落盘时**同时**写三样东西——`node_id`、**完整参数快照**、**可作为输入的类型/形状**。有了参数快照，任意产物就能"反向实例化"成一个预填好的节点；有了类型，前端就知道它能拖到哪些端口上。这一步不需要新表、不需要新服务，只需要在产物元数据里多三个字段。

### 附：三条"抄错方向"的对照（防误读）

1. **"ComfyUI 有节点缓存，所以 FE 也该有"** —— 错。ComfyUI 的缓存服务于"改一个末端节点不重跑全图"（Partial Execution），而 FE 的重跑服务于"再抽一张更好的卡"。同一个机制在两个场景里语义相反。要抄的是**局部执行**（机制 11），不是缓存本身。
2. **"Nextflow 的 task hash 有 13 个字段，所以 FE 也该有 13 个"** —— 错。字段越多命中率越低；Nextflow 的字段是为"生物信息流水线要能发表级复现"付费的。FE 只需要 5 个：节点类型、节点实现版本、输入摘要、模型文件摘要、量化档。
3. **"Temporal 的 Workflow 默认不重试，所以 FE 的图也不该重试"** —— 错。Temporal 的 Workflow 是**确定性编排层**，FE 的"图"里每个节点都是非确定性的 Activity（采样、LLM、TTS），对应的正确类比是 Temporal 的 **Activity**——默认重试。
4. **"Windmill 的 suspend/approval 很好，所以 FE 该做审批流"** —— 半错。FE 是单机单用户，没有"审批者"这个角色。要抄的是**"挂起 + 恢复 URL"这个机制的形状**（让长任务不占资源地等人），而不是企业审批语义。角色就是用户自己，按钮就是"通过 / 重拍 / 改参数重跑"。

## 4. 落地顺序建议（按"依赖关系 + 成本"排，非按收益）

| 阶段 | 动作 | 依赖 | 成本 | 对应机制 |
|---|---|---|---|---|
| P0 | 产物元数据加 `node_id` / 参数快照 / 输入类型；产物路径加 `run_id` + `shot_idx` + `attempt` | 无 | S | 12、Metaflow 身份 |
| P1 | 失败语义二维表（可重试 × 需要人）+ `allow_retries` 等效开关 + 按 message 正则的 retry 判定 | P0 的 attempt 字段 | S | 6、7 |
| P2 | 缓存严格度分级 + 缓存键 5 字段 + 命中后二次校验产物/退出码 | P0 的产物元数据 | M | 1、2、3、4 |
| P3 | 心跳式进度与"多久没进度"超时 | 引擎侧 ComfyUI `/progress` 转发 | M | 8 |
| P4 | 局部执行（选输出节点跑上游闭包） | P2 的缓存层 | S | 11 |
| P5 | step pin / mock（钉住满意的镜，只重跑其余） | P2、P4 | S | Windmill step_mocking |
| P6 | 挂起等人（质量门控第三种态）+ 一次性恢复 token | P0 的产物元数据 | M | 10 |
| P7 | 子图折叠为可复用单元 | 画布模型 | M | ComfyUI subgraph |
