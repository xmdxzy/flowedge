# 多模态出片手册（FlowEdge / MiniMax-H3）

> 这是把 2026-10-19 一整天（含 30 秒成片两轮实战）的经验压缩成的一页决策 + 一页参数 + 一页排错。
> 目标是**下次直接照做**，不再从零试。原始证据在 `AGENTS.md` 与 `.workbuddy/memory/`。
> ⚠️ **2026-10-25 形态已变**：FlowEdge 不再是"自由画布"，改成 7 条固定流水线（`data/pipelines.json`）。
> 本手册的**参数、时长、提示词模板、验收与排错**仍然有效；
> 但凡出现"建工作流 / 连节点 / 任务书 spec / POST /api/workflows"，按 `docs/多模态出片台-v2.md` 的新做法执行
> （`POST /api/produce {pipeline, params}`）。

## 一、先选路：这笔活该走哪条链路

| 你要的东西 | 走哪条 | 关键点 |
|---|---|---|
| 有人物说台词、口型要对 | **ref2va + 参考音频**（`h3_r2v`） | 只有它暴露 `ref_audios`；`fully_copy` 让音频 1:1 透传 |
| 只要氛围/打斗，没人说话 | **fl2va**（`h3` / `h3_i2v`） | 必须填满声音字段 + 口型可见事实，否则模型自己编台词 |
| 角色要在多段/多镜里长得一样 | **ref2va + 定妆图**（`ref_images`） | 身份由图像锁，不靠文字描述 |
| 单镜 ≤15 秒 | 一次生成 | 124 帧 ≈ 5.17s，243 帧 ≈ 10.1s，362 帧 ≈ 15.1s |
| 长于 15 秒 | **分段 + 装配**（`shot-film.py`） | 每段都带同一组参考图 |

**铁律**：T2V 的台词不可控（实测中文会退化成「枉年 赏我鸡肉海鲜」这种伪中文）。
要台词就上 ref2va，别在 T2V 里硬写。

## 二、先设计门，再开机（控制门）

### 为什么不能用固定表

「每个镜头多少秒」**没有恒定答案**。30 秒斗法和 15 秒广告、8 秒情绪特写，节奏结构完全不同；
同题材换一个导演，切点也不一样。所以这里不提供"该多少秒"的答案，而是提供
**一套把判断写下来、并机械校验的机制**——每次开工前你必须先声明，机器负责检查它自不自洽。

固定表格最大的危害不是不准，而是**让人跳过「先想清楚」这一步**。所以本节给出的是
「起点参考 + 怎么改」，而最终答案必须落在 `plan.gates` 里。

### 五层门

| 层 | 管什么 | 关键字段 |
|---|---|---|
| `timing` | 节奏 | `target_seconds` / `tolerance_seconds` / `min_shot_seconds` / `max_shot_seconds` / `beat_weights` |
| `identity` | 角色 | `stills`（定妆图数）/ `require_ref_images_every_segment` / `max_ref_images` / `require_picture_tags` |
| `audio` | 声音 | `dialogue.must_transcribe` / `ambience.must_be_silent` / `loudness_db` / `max_silence_gap` / `segment_retry` |
| `technical` | 技术 | `min_width` / `min_height` / `must_have_audio` / `av_drift_max` / `fade` |
| `budget` | 成本 | `wall_seconds_max` / `per_segment_wall_max` / `on_exceed` |

### 三步流程（每次任务都要走）

```bash
# 1) 出草案：只给「总时长 + 各段叙事功能与权重」，不给秒数
python scripts/film-gates.py plan --profile narrative --seconds 30 \
    --beats setup=1.0,clash=1.35,finish=1.2 \
    --modes dialogue,ambience,dialogue --lines-per-seg 1,0,2 \
    --stills 2 --min-shot 1.2 --budget 1500
# → 得到 gates 草案 + 建议帧数（按权重分配后吸附 17k+5 网格）
#    落盘后把 gates.profile 改成本片的名字（如 duel-30s-3shot），便于回溯当初怎么想的

# 2) 按本条片子的内容改写草案，写进 plan.json 的 gates
#    （改 min_shot / max_shot / 权重 / 音频政策 / 预算——不要照抄）

# 3) 验门：不自洽就不许开机
python scripts/film-gates.py check --plan data/film/jindan/plan.json
```

`shot-film.py` 会**自动**跑第 3 步；`plan` 里没有 `gates` 直接拒绝执行
（`--no-gates` 只留给调试）。序策图 `02-…` 里 `P0 → 门自洽门` 是硬前置，
门不过则无驳回边 → 运行终止，绝不浪费一次 20 分钟的出片。

### 预置 profile：从哪儿开始改

`film-gates.py plan --profile <name>` 会先套用一组门起点，再用命令行参数覆盖。
**profile 不是标准答案**，是"这条片子大概属于哪类，从这组数开始调"。

| profile | min_shot | max_shot | 总长容差 | 段级重试 | 静音缺口 | 超预算 |
|---|---|---|---|---|---|---|
| `narrative`（默认） | 1.2 | 4.5 | 0.75 | 1 | 1.0 | warn |
| `quick-cut`（15s 内 4–6 段） | 0.8 | 2.5 | 0.4 | 1 | 0.6 | warn |
| `long-take`（情绪长镜/独白） | 2.0 | 不限 | 1.0 | 1 | 1.2 | warn |
| `dialogue`（对话戏，口型是命门） | 1.5 | 6.0 | 0.75 | 2 | 0.8 | warn |
| `batch-night`（夜间批跑，宁拦不拖） | 1.0 | 5.0 | 0.75 | 0 | 1.0 | **fail** |
| `ambience-only`（纯氛围） | 1.5 | 6.0 | 0.75 | 1 | 0.7 | warn |

叠加规则：`DEFAULT < PROFILE < 本片 gates < 命令行显式参数`。
所以 `--min-shot` 这类参数默认是 `None`——如果给 1.2 这种默认值，会把 profile 静默盖掉
（这个坑当场踩过一次：`--profile quick-cut` 的 min_shot 仍是 1.2）。

### 权重怎么定：这是唯一需要你判断的地方

不要问「哪一段该多长」，问「这段承担多少叙事重量」。权重是相对的，脚本按比例分配：

| 叙事功能 | 权重起点 | 说明 |
|---|---|---|
| 定场 / 建立 | 0.8–1.1 | 交代空间与人物位置，够看懂就走 |
| 对话单回合 | 1.0–1.3 | 一句台词 + 一次反应，留出呼吸 |
| 交锋 / 高潮主体 | 1.3–1.6 | 动作密度最高，观众要看清每一次攻防 |
| 收招 / 情绪落点 | 1.1–1.4 | 台词 + 留白，是印象停留的地方 |

改权重的信号：**内容写不进去**（镜头数挤在段里）→ 加权重；**观众会走神**（一段只有环境声）→ 减权重。
这两条比任何秒数表都可靠。

### 起点参考（当成默认值，不是结论）

| 叙事功能 | 常见落点 | 帧数（17k+5） |
|---|---|---|
| 建立/定场 | 6–8s | 158 / 175 / 192 |
| 对话单回合 | 6–10s | 158 / 192 / 226 |
| 交锋主体 | 11–15s | 277 / 294 / 328 / 362 |
| 收招定格 | 9–11s | 226 / 243 / 260 |

要改就改门，别直接改帧数——改门会连带校验镜内切点，改帧数只会让某镜被压到 0.7 秒才发现。

### 门的取值怎么随任务变（示例）

| 任务类型 | 该动的门 | 怎么动 |
|---|---|---|
| 快节奏短视频（15s 内 4–6 段） | `min_shot_seconds` | 降到 0.8–1.0，允许快切 |
| 情绪长镜 / 独白 | `min_shot_seconds` / `max_shot_seconds` | 抬到 2.0，放开上限（0） |
| 无对白纯氛围 | `audio.ambience.must_be_silent` / `loudness_db` | 保持 silent=true，响度放宽到 [-24,-14] |
| 多人对话戏 | `identity.stills` / `audio.segment_retry` | 每角色一张定妆图；台词段重试 2 次 |
| 算力紧张 / 夜间批跑 | `budget.wall_seconds_max` + `on_exceed=fail` | 让超预算直接拦，不拖到天亮 |
| 交付级（客户片） | `technical.av_drift_max` / `loudness_db` | 收紧到 0.1 / [-18,-14] |

### 门能抓住什么（三个实测反例）

| 反例 | 门检结果 |
|---|---|
| 把 8.0s 的段改成 5.875s，切点仍写在 3.5/6.1 | `FAIL shot_too_short`：第 3 镜只有 **-0.225s**；`FAIL shot_tail`；`FAIL total_seconds` |
| 台词表改成「你输了」但提示词还是「让开」 | `FAIL line_mismatch`：TTS 念台词表、画面按提示词，必然对不上 |
| 提示词写 `<Picture 5>` 但只有 2 张定妆图 | `FAIL picture_overflow` |

### 门必须有牙齿

只有"能拦住"的门才算门。同一条 3 秒片段、同一个参数：

| 门 | 结果 |
|---|---|
| `--max-silence 1.0 --gate` | WARN → 通过（实测缺口 0.49s / 0.92s） |
| `--max-silence 0.8 --gate` | **FAIL `silence_gap` 0.92s（门上限 0.8s）** |
| 台词模式漏传 `--expect` + `--require-expect` | **FAIL `expect_missing`**（以前会静默通过） |

**但门不要设成你以为的"高标准"**：3 秒测试片只有一句「站住」，其余是静音，门设 0.8 会误判——
正解是给 `dub-track.py` 混环境底噪，不是放宽门。已交付的 30 秒片在 0.8s 门下 OK
（有音效填满），说明**门值要按片子解释，不能跨片照搬**。

同理，任何"只报 WARN 不拦"的检查都是装饰品。新加检查时先问：它能 FAIL 吗？不能就不是门。

### 一次真实闭环（门不是判官，是提问器）

3 秒测试片、一句「站住」，门设 `max_silence_gap=1.0`：

| 版本 | 段级门 | 尝试次数 |
|---|---|---|
| 没配环境底噪 | **FAIL** `silence_gap 1.22s` → 重跑 → 仍 **FAIL** `1.06s` | 2（retry 用尽，整片失败） |
| 给 `dub-track` 混了 `--ambience` 底噪 | **通过**（静音被填满，ASR 仍转出「站住」） | 1 |

这里的门报的不是误判：3 秒镜头只有两个字台词，其余是**死寂**，观众听到的就是"说完就没了"。
正确反应是**补底噪**，不是把门放宽到 1.3s。门的作用是把这个决定从"没注意到"变成"必须表态"。

反过来，同一门值放在 30 秒成片上 OK（有音效填满）——所以**门值要按片子解释**。

### 段级门：早失败才省时间

`shot-film.py` 在**每段出片后立刻**验一段（技术项 + ASR 政策），不合门按
`audio.segment_retry` 重跑，仍不过才放弃：

- 台词段：`verify-media --asr --expect "<本段第一句>"`
- 氛围段：`verify-media --asr --no-speech`

以前是全片跑完才发现某段念错，只能整批重来；现在最多浪费一段。

## 二·附、一条 30 秒片的实际取值（照抄也没错，但要理解为什么）

```json
"gates": {
  "profile": "duel-30s-3shot",
  "timing":   {"target_seconds": 30, "tolerance_seconds": 0.75,
               "min_shot_seconds": 1.2, "max_shot_seconds": 4.5,
               "beat_weights": {"setup": 1.0, "clash": 1.35, "finish": 1.2}},
  "identity": {"stills": 2, "require_ref_images_every_segment": true, "max_ref_images": 9},
  "audio":    {"loudness_db": [-20, -11], "max_silence_gap": 0.8, "segment_retry": 1},
  "technical":{"min_width": 608, "min_height": 352, "must_have_audio": true, "av_drift_max": 0.2},
  "budget":   {"wall_seconds_max": 1500, "per_segment_wall_max": 600, "on_exceed": "warn"}
}
```

结果：192 + 277 + 260 = 29.98s，实测 720 帧 / ASR 三句齐全 / 墙钟 640s。
`min_shot=1.2` 的来源：低于 1.2 秒，观众读不到「谁在做什么」；`max_shot=4.5` 的来源：
斗法里单镜超过 4.5 秒会泄气——这两个数可以改，但改的时候要能说出依据。

## 三·零、图里有字怎么办（MOSS-Image，2026-10-23 落地）

**一句话**：flux 画不出可读文字——它只会画出"像字的笔画"。
图里需要出现可辨认的中/英文（招牌、海报、字幕板、封面标题、UI 标注），
把文生图节点的 `backend` 设成 `moss`。

| 场景 | 后端 | 说明 |
|---|---|---|
| 分镜图 / 角色表 / 氛围图（无字） | `flux`（默认） | 4 步，3 秒一张 |
| 图里要有可读文字 | `moss` | 50 步实测 44–48 秒；8 步 10 秒（字照样对，画面糙） |
| 不知道 | `auto` | 填了 layout 或提示词命中文字信号 → moss，否则 flux |

**布局控制**（MOSS 专有，flux 没有）：给 bbox，元素就会落在指定位置。

```json
[{"type":"text","text":"山海茶肆","bbox":[80,120,220,880]},
 {"type":"object","desc":"一只白鹤站在石碑上","bbox":[400,200,900,700]}]
```

bbox 是 **0-1000 归一化** `[y0,x0,y1,x1]`，原点左上——改分辨率不用重画框。
也可以由上游 JSON 端口喂进来（比如让 LLM 先出一份版式）。

**两条纪律**

1. **别用 flux 硬凑文字**。见过最多的返工就是"提示词里写了字，出来是一团笔画"，
   然后花三轮调提示词——这不是调参能解决的结构问题（AGENTS §0.12 ③）。
2. **MOSS 的图别和 flux 的图混在同一批跑**。两者不在同一个进程，
   切换要先 `/free` 腾显存（引擎已自动做），代价是下一次 flux 要重新冷加载 ~183s。
   把出片流程里"有字的图"聚在一起跑。

## 三、提示词：两种结构，别混

> 事实源：官方 `github.com/MiniMax-AI/MiniMax-H3/skills/h3-prompt-writing/references/`
> 的 `base-en.txt`（基础模式）与 `ref-en.txt`（全参考模式）。社区博客里流传的简化版会漏掉关键约束。

### T2V / I2V（三段式，英文）
```
integrated_multimodal_description: [Shot 1] <第一句先立风格> …
overall_soundscape: …
non_diegetic_music: N/A
```

### R2V（六段式，英文）
```
subject_definitions: <Subject 1> is … in <Picture 1>, …
summary: [reference generation + audio reuse] …
retention_analysis: <Subject 1> (appears in [Shot 1]): fully_preserved - …
                    <Audio 1>: fully_copy - is reused 1:1 as the target video's complete final audio track.
detailed_description: <风格句> [Shot 1] …（替代 integrated_multimodal_description）
overall_soundscape: The copied ambience layer from <Audio 1> continues throughout the target video.
non_diegetic_music: N/A - any score present is part of <Audio 1>'s copied track.
```

**七条硬规则**
1. **字段不能空**：空着 `overall_soundscape` / `non_diegetic_music`，模型会自己填（含即兴人声）。
2. **身份写 Subject 不写 Picture**：图片只用来定角色/服装时，`<Picture N>` **不得**单列成
   "defines the visual identity"，必须写成 `<Subject N> … in <Picture 1>`。帧锚点才用 Picture。
3. **不写否定清单**：cfg=1 没有负分支，"no dialogue / silent" 无效甚至反效果。
   压人声用可见事实：`lips stay closed and still, jaw tight, breath audible through the nose`。
4. **说话人要"能念"**：`(S1)` 前给音色/年龄/性别/语速（`with a low, gravelly voice`），
   身份与动作在 `<d>` 外，`<d>` 内只放 `[Chinese]` + 原文原标点。台词的 `<d>` 标签**不能丢**。
5. **多镜头用时间戳**：`[Shot 2] At 00:03.500, the camera cuts to …`，不给区间；`[Shot 1]` 不带时间戳。
6. **镜头运动用官方词汇**：Push In / Pull Out / Pan / Truck / Tilt / Pedestal / Arc / Tracking / Zoom /
   Static / Shake / POV / Roll。幅度与速度**只在有意义时写**（官方允许省略）。
   不要用 `moves forward`、`camera follows` 这类表达。
7. **正文要够长**：Ref2VA 的 `detailed_description` 目标 350–500 词；每镜写清构图、人物、环境光、
   动作与状态变化、镜头运动、该刻声音、参考在哪生效。

> 引擎把上面这些做成确定性体检（`auditH3Prompt`）：漏字段、Picture 身份误用、说话人无音色、
> 有音频没标 fully_copy、`summary` 前缀与实际资产矛盾、标签裸写——都会在日志里报出来。
> 台词被模型改写或翻译时直接退回原文重搭结构（`protectDialogue`）。

## 四、角色一致性：定妆图 > 文字描述

```
flux 出定妆图（正面、干净背景、露出服装与法器）
  → 每段都传 ref_images（≤9 张）
  → 提示词 <Picture N> 指认 + retention_analysis: fully_preserved
```

实测（608×352，三段）：青袍/黑袍、束发玉簪、白骨法杖、红瞳全部守住。
**边界**：锁得住服装·法器·剪影·配色，锁不住高相似度五官——低分辨率下脸没多少像素。
243 帧 + 2 张参考图已用满 24GB（剩 ~0.6GB），想提分辨率只能缩时长或减参考图。

### 场景一致性：九宫格锁（与角色锁配套）

角色有定妆图，**场景没有**。多段生成最典型的坏片是：帧数、时长、音频全部正常，
接缝处却换了场地——因为每段独立采样，光位与道具摆放各自漂移。

做法：把画面切成 3×3，一格一个空间区域，只写看得见的物理事实，编译成一句
`SCENE LOCK`，**逐字**注入每一段。

| 层 | 格位 | 写什么 |
|---|---|---|
| 远景 | 上排三格 | 天花、天空、墙面上部、悬挂物 |
| 中景 | 中排三格 | 柱、门、建筑立面、主体所在层 |
| 近景 | 下排三格 | 地砖、台阶、积水、散落物 |

外加 `light`（方向+色温+硬度）、`palette`（主色关系）、`depth`（机位高度+焦段）。

**四条硬约定**（违反任一条锁句就失效）：

1. 格位内容**不许有句号**（锁句边界靠第一个句号界定）
2. 格位内容**不许有分号**（与格位分隔符冲突）
3. 必须**英文**（中文格位会被弱化，体检报 `scene_lock_not_english`）
4. **不写形容词**，写材质、颜色、形状、位置关系

注入点：T2VA 插在 `[Shot 1]` 风格句之后；Ref2VA 插在风格句之后、`[Shot 1]` 之前。
不靠 LLM"记得保留"——它会改介词，字节一变一致性就没了。

门：`auditSceneConsistency` 按**原文全等**比对各段锁句，
`h3.scene_lock_missing` / `h3.scene_lock_drift` 都是 FAIL，进 `prompt_warnings`。

节点用法：

```
场景九宫格节点（手填 9 格，或给一句 idea 让 LLM 拆）
  → lock 连到 文生视频.scene_grid（也可直接粘贴 SCENE LOCK 句）
  → segments>1 时引擎逐段重注 + 校验字节全等
```

**边界**：锁得住空间布局、光位、材质、色调；锁不住人脸与高相似度细节。
场景锁与定妆图冲突时，图里已经有的结构不要重复写进格位，只写图里没有的层。

### 像素侧：一致性门（2026-10-23 新增）

九宫格锁守的是**文本侧**：各段收到同一句锁句。它守不住**结果**——
模型收到同一句锁句仍然各自采样，成片看着换了场地，而时长、帧数、锁句三项**全部正常**。
（这正是"验收维度选错、用工具没报错当没问题"那一类坑。）

所以补一道**像素侧**的门：`consistency_gate`，挂在五层门的 `identity` 层。

```
文生视频 / 分镜执行 → parts（有序）→ 一致性门 →（FAIL 就地阻断）→ 后续
```

三条判据，**各自独立判、各自单独报**，不合成总分（加权总分会让"布局全变但色调没变"
被"色调没变"掩盖）：

| 判据 | 度量 | 抓什么 | 抓不到什么 |
|---|---|---|---|
| `layout` | 九宫格**块色相**直方图巴氏系数均值 | 陈设/构图/局部换景 | 纯曝光变化 |
| `palette` | 全局 HSV 联合直方图巴氏系数 | 整体色调漂移 | 结构变化 |
| `luma` | 整帧平均亮度差 | 换了个曝光 | 换色（前两条抓） |

默认阈值（**标定过的**，拿本机真实成片做受控变换量出来）：

| 变体（真值） | 布局 | 配色 | 亮度差 | 判定 |
|---|---|---|---|---|
| 亮度 +4%（同） | 1.000 | 1.000 | 0.007 | PASS |
| 色相 +5°（同） | 0.997 | 0.995 | 0.000 | PASS |
| 5% 噪声（同） | 0.993 | 0.985 | 0.043 | PASS |
| 裁切 3%（同） | 0.998 | 1.000 | 0.002 | PASS |
| 色相 +120°（异） | 0.394 | 0.570 | 0.015 | FAIL |
| 上半换色（异） | 0.673 | 0.842 | 0.044 | FAIL |
| 亮度 -35%（异） | 1.000 | 0.965 | **0.081** | FAIL（只有亮度差抓到） |

默认值：布局 ≥0.94 / 配色 ≥0.92 / 亮度差 ≤0.07。最后一行是"三条缺一不可"的证据。

报错会给**格位名**（与九宫格同一套名字），直接对应要改的那一格：

| FAIL 项 | 改哪里 |
|---|---|
| `*_layout` | 打开分镜 `continue` 转场（下一段用上一段末帧开场）；把该格位写死到材质与数量 |
| `*_palette` | 填九宫格 `palette` 字段；确认各段复用同一份锁句 |
| `*_luma` | 填九宫格 `light` 字段，把光源写进具体格位 |

**两个使用纪律**：

1. 必须吃 `parts`（分镜的有序段数组）。按 id 排序时输出会带 `warning`，结论不可信。
2. 新类型片子先勾 `warn_only` 跑一遍看数值分布，再定阈值。
   **不要为了过门而调松阈值**——那等于把门拆了。

**边界**：证明"画面像不像"，不证明"好不好看"，也不替代质检门（帧数/时长/响度）。

## 五、声音：自己做，别指望模型

| 场景 | 做法 |
|---|---|
| 有台词 | TTS（Kokoro）逐句合成 → 按帧数对齐 → `fully_copy` 透传 |
| 要环境声 | 混进同一条 wav（`dub-track.py --ambience`），因为 fully_copy 是全音轨 |
| 只想压住乱语 | 中置相消 `pan=stereo\|c0=c0-c1\|c1=c1-c0`（人声居中、环境声宽） |
| 验收 | ASR 必须能转出剧本原话；无人声镜头必须转不出字 |

**参数**：`turbo` 默认 **12 步**（官方：台词与音色需 12+ 步，8 步音频是短板）；
sigma shift turbo 为 video 12 / **audio 6**，base 为 12 / 3。

## 六、参数与耗时（3090 24GB 实测）

| 配置 | 单段耗时 | 峰值显存 |
|---|---|---|
| 192 帧 / 12 步 / 2 参考图 | 178s | ~23GB |
| 260 帧 | 226s | 23.4GB |
| 277 帧 | 236s | 剩 ~0.6GB（已到上限） |
| 三段共 729 帧（192+277+260） | **640s ≈ 10.7 分钟** | — |

单帧成本约 **0.85–0.93 s/帧**；固定成本：H3 冷启 ~50s、换 checkpoint ~30–60s。
同一批曾出现单段 556s（≈2.4 倍），属偶发争用，不是帧数的正常代价——
**报时间按 3–5 分钟/段（200–280 帧）估，留一次异常余量**。

## 七、交付前必须过的验收

```bash
python scripts/verify-media.py 成片.mp4 --asr [--expect "原话"] [--no-speech] --gate
```

| 检查 | 抓什么 |
|---|---|
| 流 + 时长 + **精确帧数** | xfade 短于一帧会整段丢画面，时长看不出来 |
| 有效帧率 ≈ 标称 | 同上，帧数比时长诚实 |
| 音画时长差 >0.2s | 拼接丢段 |
| **语音起点 vs 计划时点 ≤0.12s** | TTS 自带前导静音，`av_drift` 永远看不出来；`shot-film` 现在会自动比对并告警 |
| **跨段 AvgY 极差 ≤25** | 重拍某一镜最容易毁掉时间感（实测 68 → 107）；`shot-film` 装配前自动测并写进 `film-report.json` 的 `exposure` |
| **段间一致性（布局/配色/亮度差）** | 多段片在装配前挂 `consistency_gate`：锁句全等但画面换场地，只有像素侧抓得到。见第四章「像素侧：一致性门」 |
| 中段静音 >0.45s | 接缝断音 |
| 响度（max/mean） | 削波 / 近乎无声 |
| ASR | 台词是否念对 / 是否冒出人声 |

退出码 0/1/2；`--gate` 只有 FAIL 才拦。**FAIL 一律不交付。**

## 八、失败模式速查

| 症状 | 根因 | 修法 |
|---|---|---|
| 角色说含糊假台词 | 步数 8 / 缺 sigma 节点 / 声音字段空 / 用了否定式 | 12 步 + 12/6 + 三段式 + 口型事实 |
| 换段就换脸 | 只靠文字描述角色 | 定妆图 + ref_images 每段都传 |
| 接缝闪一下 | 硬拼 | xfade 0.2 + acrossfade 0.2 |
| 某段没声音 | 该段音频几乎是静音 | 逐段测响度（< -42dB 重生成） |
| 时长对但没画面 | xfade d < 一帧 | d ≥ 0.08，offset 留一帧 |
| 念稿变伪中文 | 参考音频没标 `fully_copy` | retention_analysis 明确写 |
| 台词与镜头错位 | wav 里台词位置没对齐切点 | `dub-track --lead` 对齐 |
| 报「3s 内未就绪」 | 依赖启动等待写死 3s | 已改为按类型（H3 180s） |

## 九·附、canonical 出片工作流（整本手册的一条图）

第二到七章的所有纪律，已经编译成一条**引擎内可运行**的工作流——不用记命令，
在画布上打开、改 prompt 和 plan 就能出片；每道门的牙齿都在图上，跑就知道拦不拦。

- 文件：`data/workflows/canonical-film.json`（导入用）
- 线上：引擎 DB 工作流 **#113**（30s 三镜参考实现，jindan 派生）
- 任务书：`data/workflows/canonical-film-spec.md`（`GET /api/workflows/113/spec?format=md` 随时重导）
- 自检：`python scripts/verify-canonical-live.py`（35 项在线断言：五层门 / 17 个阈值 / 四门节点 / 菱形汇合）

### 拓扑：菱形汇合在质检门

```
start-1 ──▶ sl-1（分镜 + 五层门预检，require_gates=true）
              ├─▶ cg-1（一致性门：像素侧）
              └─▶ pp-1（后期：字幕 / BGM 侧链 / 响度两遍法归一）
                     cg-1 ─┐
                          ├─▶ qg-1（质检门：交付前最后一关）──▶ end-1
                     pp-1 ─┘
```

为什么是菱形而不是串串：一致性门与后期互不依赖，必须能并行；
但质检门**必须同时等两者**——任一门 FAIL，都要在交付前最后一关被拦住，
而不是「后期跑完了才告诉你不一致」。

### 每道门拦什么（按图，值为画布真实值）

| 节点 | 门层 | 牙齿 | FAIL 条件 |
|---|---|---|---|
| sl-1 | timing / identity / audio / technical / budget | plan.gates 五层：target 30s、stills 2、响度 [-20,-11]、min 608×352、预算 1500s | 预检不过**不开机**（不烧显存） |
| cg-1 | identity（像素侧） | layout_min 0.94 / palette_min 0.92 / luma_max 0.07 / 漂移 0.92 / 0.90 | 锁句字节全等但画面换了场地 |
| pp-1 | technical + audio | loudness -16 / duck true / aspect keep | 响度不归一、侧链没生效 |
| qg-1 | audio / technical | min_frames 700、时长 25–35s、max_silence_gap 5.0、loudness_min_db -20、require_audio | 帧数不够、中段掉音、暗噪、没音轨 |

段级失败不用整片重跑：引擎续跑（`RunService.Resume`）只补失败的节点，
五层门 + 段级门保证「哪段坏了知道是哪段」。

### 用它出片

1. 客户端打开工作流 #113（或导入 `canonical-film.json`）
2. 改 `start-1` 的 prompt 讲你要的片子；`sl-1` 的 plan 按第二章流程重新设计门
   （`python scripts/film-gates.py plan ...` → 贴进 sl-1 的 plan 参数，**别照抄本章的值**）
3. 跑。任一门 FAIL 停在该节点，错误直指哪一层哪条规则。

### 这张图替你守住的坑（都是实测摔出来的）

- **负 dB 阈值曾全线失效**：`loudness_min_db` 天然是负分贝，旧解析 `v > 0`
  把一切真实阈值静默丢弃——门看着配了，其实永远不查。已修，
  `TestParseGateRules_LoudnessMinDBSigned` 钉住。
- **声明门层却没有阈值 = 没设门**：任务书会给这种节点记警告（canonical 图上为 0 条）。
  一致性门的阈值键（`layout_min` 等）已进门的词汇表，`post_production` 补登记 audio 层——
  否则它的响度归一会被判「裸门」，自进化也会失去对它的保护。
- **静音缺口容忍片头 lead-in**：质检门取 5.0s 而不是 plan 的 0.8s——
  0.8s 会被片头 4.1s 前导静音直接判死；5.0s 抓的是中段掉音。
  两个值不在一个口径：0.8s 是预检层的拼接纪律，5.0s 是交付层的容错。

## 十、一句话总结

**先用门把判断写下来，再让机器检查它；能用图锁的别用字描述，能提前合成的别交给模型，
能机械验的别靠肉眼看，能按内容分配时长的别均分。**

更短一句：**没有门的流水线，只是在批量生产"看着还行"。**
