# 图里有字必须走 MOSS，flux 只会画出像字的笔画

**规则**：画面里需要出现**可辨认**的中/英文字（招牌、海报、字幕板、封面标题、包装、UI 标注）时，
文生图节点的 `backend` 必须是 `moss`。`flux` 在这件事上没有能力，换 checkpoint 也没有。

**数值**：

| | flux-schnell-fp8 | MOSS-Image SFT |
|---|---|---|
| 步数 | 4 | 50（官方推荐）；**8 步也能把字写对** |
| 1024² 单张 | 约 3 秒 | **实测 44–48 秒**（8 步 10 秒 / 25 步 25–30 秒） |
| 显存峰值 | 约 17GB | **实测 10–13GB**（连续跑偶发贴到 23GB） |
| 图内文字 | 不可用 | 原生渲染中英文 |
| bbox 布局 | 无 | 有 |

**文字正确性不随步数塌方**：8 步出图的「山海茶肆」逐字正确，步数影响的是画面整体质量
（8 步裁切偏紧、背景糊；50 步雾层与细节完整）。所以**只要字**可以降到 8 步，
**要成片级**再用 50 步。

bbox 用 **0-1000 归一化** `[y0,x0,y1,x1]`、原点左上；改分辨率不用重画框。
`type` 填 `text` 时 `text` 字段就是画面里要写的那几个字。

**为什么**：扩散模型的文字能力来自训练数据里的字形条件，不是来自提示词里的"请写得清楚一点"。
flux 训练时几乎没见过需要精确排版的中文，于是它学到的只是"文字大概长什么样"——
笔画数量、部件位置全凭概率，出来就是一堆看着像字的形状。
MOSS 有独立的 9B 文本编码器和显式的 bbox 条件，字的内容和位置都是**输入**而不是猜测。

**验证**：出图后把文字区域裁出来放大，**逐字**对照。乱码 / 缺笔 / 错字 / 多字 = FAIL。
字错时先检查 layout 的 `text` 字段是不是你要的字（引擎拼 JSON 时传错一个字节就会渲染成别的字），
再检查 bbox 是否太小（框太小模型会压缩字形导致糊）。
**不要靠改提示词修字**——那是拿调参掩盖结构问题，改十遍也只会得到十遍糊字。

**配套**：`backend=auto`（默认）会在提示词命中"写着/标题/字幕/海报/招牌/排版/logo"等信号时
自动切到 MOSS，并可在节点输出里看到 `backend_reason` 说明为什么选了它。
结论不确定时就把 `backend` 显式设成 `moss`，别让启发式替你做决定。
