# 代码知识片 · 四套视觉风格体系（2026-10-31）

> 起因：用户反馈「现在视频风格太差劲」，要求把调研到的头部知识科普视觉方案真正落地。
> 调研来源见 `docs/调研-Vibe知识科普前沿方案-20261030.md`。

## 一、结论先说

`code_video` 从「只有一套蓝图模板」变成**四套风格 + 一层设计 token**：

| 风格 id | 对标样本 | 视觉签名 | 画幅 |
|---|---|---|---|
| `darkcard` | 抖音「基地」（440 万粉，2K60，−19.9 LUFS / LRA 2.0） | 暗色 3D 卡片世界、准一镜到底、三色纪律（白 + 薄荷绿 + 紫） | 16:9 |
| `studio` | anything2explainer（2.8k★，黑画布 MG + 章节进度条） | 纯黑底、超大无衬线、单一电光蓝、底部分段章节条 | 16:9 |
| `atlas` | 小红书《把北京地铁切开》（封面点击率 15.4%、赞藏比 1.8:1） | 羊皮纸米色 #F0EDE6、思源宋体、剖面图 + 细折线引线标注、页码序列 | 自适应 |
| `blueprint` | 首版自研（工程蓝图 + 手绘白线） | 深海军蓝、手绘抖动线、打字机 | 16:9 |

默认风格改为 `darkcard`（`data/pipelines.json` 的 `knowledge_film`）。

## 二、三层结构

```
backend/service/codetpl/
├── shared/
│   ├── kit.js        第 0 层：确定性数学 / 排版 / 纹理（clamp、wrapByPunct、makeGrain…）
│   └── tokens.js     第 1 层：设计 token —— 配色、字号阶（改色只改这里）
├── darkcard/         第 2+3 层：卡型 blocks + 场景 world（index.html + render.js）
├── studio/
├── atlas/
└── blueprint/
```

- **tokens 层为什么必须有**：调研头部账号得出的结论是「好看不是审美，是可复用的约束」——
  「基地」15 分钟不出现第四种强调色，靠的是一份写死的 token 表，不是每帧现调。
  所以配色集中在 `shared/tokens.js`，`render.js` 里不许再手写 `#RRGGBB`。
  DOM 型风格（darkcard）用 `applyCssTokens()` 把 token 写进 CSS 变量，CSS 里保留同名兜底值。
- **blocks 层**：四类卡型 —— 大字金句卡 / 图表卡（bars）/ 对比面板 / 剖面图版。
  同一套 `CodeSpec` 数据，四种风格各自渲染自己的卡型。
- **worlds 层**：每个风格目录 = 一个可换肤的世界（暗色走廊 / 黑画布 / 纸面图鉴 / 蓝图稿纸）。

## 三、怎么用

**出片台（推荐）**：`knowledge_film` 流水线新增 `视觉风格` 下拉框，四个选项直接选。

**API**：

```json
POST /api/produce
{ "pipeline": "knowledge_film",
  "params": { "style": "darkcard", "title": "标题", "points": "要点1\n要点2" } }
```

**节点直调**：`{"type":"code_video","data":{"style":"atlas","spec":"{...}"}}`

**多卡整卷**（四套风格都吃同一份 `spec`）：

```json
{ "title": "卷名", "card_seconds": 5,
  "cards": [
    { "kicker": "PART 01", "heading": "一行的结论", "points": ["要点", "要点"], "note": "NOTE" },
    { "kicker": "PART 02", "heading": "带图表", "figure": "bars",
      "labels": ["运镜", "硬切", "版式"], "values": [82, 12, 46] }
  ] }
```

## 四、怎么加第五套风格

1. 在 `codetpl/` 下建目录（**名字不能以 `_` 或 `.` 开头**）；
2. 放 `index.html` + `render.js`，实现页面契约：`window.READY / window.DUR / window.render(t) / window.TEXTS(t)`；
   只有 `render(t)` 依赖 `t`，禁止 `Math.random()` / `Date.now()`（否则逐帧不可复现）；
3. `code_video.go` 的 `codeVideoStyles` 加一行 + `codeVideoStyleNames` 加个名字；
4. `data/pipelines.json` 的 `style` 字段 `options` 加一项；
5. 跑 `FLOWEDGE_LIVE_CODEVIDEO=1 go test ./service/ -run TestCodeVideoStylesRender -v` 出片核对。

**踩过的坑（会再踩，写下来）**：
- **`//go:embed` 会跳过以 `_` 或 `.` 开头的目录**。共用层最初叫 `_shared`，
  编译通过、运行时文件根本不存在 → 现在叫 `shared`。
- **样式目录里的 `spec.json` 不会被拷贝**（执行器会跳过），spec 由节点参数生成。
- 卡片容器的 class 忘了挂，柱子会按块级元素竖着堆（darkcard 真实踩过）。

## 五、实测（本机，2026-10-31）

| 风格 | 15s / 360 帧 渲染耗时 | 备注 |
|---|---|---|
| blueprint | 21.5s | 纯 canvas 2D |
| darkcard | 26.7–31.9s | DOM + CSS 3D，逐帧截 JPEG |
| atlas | 23.6–28.3s | canvas + 纸张噪点贴图 |
| studio | 19.5–24.2s | canvas + 噪点贴图 |

- 全部走 **CPU 道**，零显存，与 H3 出片并行不抢卡。
- 验收口径：`nb_read_frames` 必须等于 `duration × fps`（差 >2 帧即 FAIL），
  再跑 `python scripts/verify-media.py`。

## 六、已知限制（别当成已完成）

- **画幅**：darkcard / studio / tlas 三套都有**独立竖版布局**（见 §八），
  lueprint 仍是横屏专用（它是首版，没做竖版）。
- **字体**：`atlas` 依赖系统里的 **Noto Serif SC / 思源宋体**（本机有全套字重）；
  换到没装思源宋体的机器会退化成 `SimSun`，观感会掉一档。
- **tokens 覆盖不全**：还有部分中间色（如暗色的 hover 态、atlas 的地层填充色）写在 render.js 里，
  下一步应全部收进 tokens。
- **无 BGM**：遵守 `AGENTS.md` 2026-10-30 的口径，知识类片子不垫乐；四套风格都只有画面。
- **未做的**：对比面板卡型（四类卡型里的第 3 类）目前只在 darkcard 有视觉骨架，其余风格未实现；
  真 3D（Blender 路线、「基地」那种连续世界）没有做，现在是 2.5D 伪透视。

## 七、真机联调抓到并修掉的两个问题（2026-10-31）

这两个都是「台架全绿、上产品就露」的类型，记下来别再犯：

1. **中文逗号把要点切碎**。`buildCodeSpec` 原来用 `splitLoose` 切 `points`，而它按
   `\n , ， ; ；` 全部切分 —— 「信息密度一样，观感差距来自版式与节奏」被静默拆成两条要点，
   成片里就是被腰斩的两句话。现在要点只按换行切（`splitPoints`），
   `labels`/`values` 那种逗号列表仍走 `splitLoose`，并有 `TestSplitPointsKeepsChineseCommas` 钉住。
2. **超时预算按台架定，真机判超时**。台架 15s/360 帧 24s（0.065s/帧），真机 8s/192 帧跑了 52s
   （0.27s/帧，冷启动 + 抢 CPU）；旧公式 `60s + 帧数×0.25`（还没除 workers）算出 1m48s，
   把一条正常片子判成 `node timeout after 1m48s`（run 386）。
   现在 `90s + 帧数×0.55/workers`，并按「宁可给宽：确定性渲染白等不亏，误杀会让用户以为节点坏了」定调。

**真机链路证据**：`POST /api/produce {pipeline:knowledge_film, params:{style:"darkcard",…}}`
→ run 388 success / 21s → `运行/data/generated/code-video-1793412695315844600.mp4`
→ `verify-media` 192 帧 / 8.0s / 1920×1080 / 仅 `no_audio` WARN（无声片属预期）→ 抽帧目检要点完整。
## 八、竖屏（9:16 / 3:4 / 1:1）

**不是把横屏挤扁**：四套风格各有独立的竖版排版，靠 `PORTRAIT` 分支 + 视口推导的设计尺寸。

### 8.1 画幅怎么选

`knowledge_film` 的 `画幅` 字段（节点 `data.aspect`）：
`16:9`（默认）/ `9:16`（抖音、视频号）/ `3:4`（小红书）/ `1:1`。
`aspect` 优先于 `width/height` —— 用户只选一个下拉框，不用同时填两个数。

### 8.2 安全区（这条最重要）

竖屏不是整个画面都归你：**顶部 ~13%、底部 ~18% 会被平台 UI 压住**
（头像、关注按钮、文案、点赞/评论条）。实测过版式排到 0.82 以下，成片上线后章节条直接被盖掉。

四套风格的竖版都把内容收在安全区内：
- 顶部内容起点：`H × 0.135`（atlas 用 0.095，因为图鉴页头更紧凑）
- 底部内容终点：`studio × 0.775`、`atlas × 0.885`、`darkcard` 由卡片自身留白保证

### 8.3 四套风格的竖版差异

| 风格 | 竖版做法 | 关键数值 |
|---|---|---|
| `darkcard` | 卡片改成 940×0.66H 的竖幅，走廊间距按卡高推（`SEG = CH×1.62`）；**下半部用超大序号（220px，7.5% 透明度）当版面锚点**，避免一整片空黑 | 标题按字数 66/58/50/44px；要点 30px、行距 26px |
| `studio` | 瑞士排版天然适合竖屏：HUD → 大字标题（92→60 五档自适应）→ 要点 → 数据区 → 分段章节条 | 标题宽 `DW-152`；数据区 `0.545H`；页脚 `0.775H` |
| `atlas` | 最自然的一种，直接按「一页图鉴」排：眉标 → 宋体标题（3 行）→ 剖面图版 → 图例 → 页码点 → 页脚；**图版高度按剩余空间预算**算，不再用固定比例 | 图版 `clamp(footY-140-图例高-plateTop, 300, 0.72W)` |
| `blueprint` | 图版重排：标题 74px（最多 3 行、按标点断行）→ 要点 42px → 图表；右下角标题栏随画布自适应 | 版心 `CX=64`；图区 `0.54H`；尺寸线 `0.815H` |

### 8.4 视口 → 设计尺寸

```
横屏：DW=1920, DH=1080            （9:16 之外的比例按 min 缩放居中）
竖屏：DW=1080, DH=round(1080*VH/VW)   → 9:16→1920，3:4→1440，1:1→1080
```
`1:1` 走竖版分支（走横版会上下加黑边）。画布按视口实际像素分配，`setTransform` 等比缩放，
所以文字在任何输出尺寸下都是原生分辨率渲染，不是先画大再缩小。

### 8.5 竖屏实测（2026-10-31，24fps / 每卡 4s / 3 卡）

| 组合 | 成片 | 帧数 | 耗时 |
|---|---|---|---|
| darkcard 9:16 | 1080×1920 | 288 | 55–64s |
| studio 9:16 | 1080×1920 | 288 | 40–67s |
| atlas 9:16 | 1080×1920 | 288 | 41–80s |
| atlas 3:4 | 1080×1440 | 288 | 33–44s |
| darkcard 3:4 | 1080×1440 | 288 | 45–63s |
| blueprint 9:16 | 1080×1920 | 288 | 17–23s |

竖屏比横屏慢约 3 倍（0.22s/帧 vs 0.067s/帧，JPEG 截图为竖幅时更贵）。
超时预算 `90s + 帧数×0.55/workers` 覆盖得住：12s 片 = 288 帧 → 169s 上限。

**真机链路**：`POST /api/produce {knowledge_film, style:darkcard, aspect:"9:16"}` →
run 391 success → 1080×1920 / 144 帧 / `verify-media` 仅 `no_audio` WARN。

### 8.6 竖屏没做的事

- 竖屏**只改布局，没改内容密度**：一条卡要点超过 4 条时会被截断（竖屏最多 3–4 条），
  内容侧要自己控字数，不是排版能兜住的。
- 竖屏下的**字幕/贴纸安全区**没做：`subtitles=true` 烧录按底部居中，抖音上会被压，需另配样式。
- `1:1` 只有分支逻辑、只跑过 atlas/darkcard 的渲染，没有逐套看过成片。
