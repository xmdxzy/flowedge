# FlowEdge v2：只剩多模态出片流程（2026-10-25）

> 一句话：**图不再由用户画**。用户在出片台选一条固定流水线、填几个字段，
> 服务端按 `data/pipelines.json` 组装节点图去跑；跑完给产物，不过门就诊断重跑。
>
> 上一版（Lite v1，2026-10-24）砍的是**生态面**（卡片/技能/触发/进化/工具链）。
> 这一版砍的是**平台形态**：画布、任意 DAG、工作流 CRUD、模板库、节点调色板/检查器、
> 任务书 spec、模块契约、估算、模型库、实例管理、LLM 配置编辑、单步调试。

## 一、为什么这么砍（判断依据，不是喜好）

1. **组合空间里绝大多数是垃圾**：27 种节点 × 任意连线的组合几乎都跑不通或没意义，
   而"哪条链路真能出片"这份知识原本只存在于模板文件和文档里，不在用户脑子里。
2. **平台配套一行都不产出多模态内容**：调色板/检查器/任务书/版本/调试，
   每一个都是为"用户自己画图"服务的，而用户从来没有画对过。
3. **收敛后仍然可配置**：pipelines.json 能改字段、改节点、改默认值，不用重编译。
   这是"轻"，但不是"写死"。

## 二、现在的产品面

### 7 条固定流水线（`data/pipelines.json`）

| id | 名字 | 产物 | 链路 | 预计 |
|---|---|---|---|---|
| `image` | 文生图 | image | start → text2image（+质量循环可选）→ end | 60s |
| `image_batch` | 分镜批量出图 | image | start → llm 拆镜 → text2image(按行批量) → end | 180s |
| `image_edit` | 图像编辑 | image | start → image2image \| inpaint \| upscale → end | 40s |
| `video` | 文生视频（带声音） | video | start → text2video(H3，可带参考图/参考音频) → end | 240s |
| `video_from_image` | 图生视频·长镜头 | video | start → text2image 定首帧 → text2video 2 段续接 → end | 420s |
| `film` | 多段短片 | video | start → storyboard 分镜表 → shotlist（五层门 + **一致性门** + 逐镜生成 + 装配）→ end | 2400s |
| `voice` | 文案转配音 | audio | start → tts（填参考音频即音色克隆）→ end | 30s |

字段语义（三条硬规矩，改 JSON 时别破）：

- `bind` 把字段值写到指定节点的 `data` 键（支持点分下钻）。**填了没生效是这里写错**，
  所以 `pipeline_test.go` 会真的组装一次并核对节点 data。
- `when` 决定节点是否入选：`"qc"`（真值）或 `"mode=inpaint"`（等值）。
- 未知字段一律 400 拒绝。拼错的 key 静默忽略会变成"我明明填了却没生效"。

## 三、质量循环怎么进固定流水线

`qc=true` 时服务端做两件事：

1. 把刚组好的图落成一条**临时工作流**（名字 `qc:` 前缀，跑完即删，启动时清扫残留）；
2. 外层换成 `start → quality_loop(workflow_id=<临时图>, max_rounds=3) → end`。

为什么是临时的而不是内嵌：`quality_loop` 的语义就是"反复重跑另一张图并择优"，
它按 `workflow_id` 从库里取图。用临时图才能保住**本次填的参数**
（否则重跑会退回 JSON 里的默认值，择优就失去意义）。

预检与保存期校验在**包壳之前**对原始图做——对壳做预检等于什么都没查，
会让"最贵的路径反而跳过预检"。

### 真机首跑（同一台机器，2026-10-25 05:00 前后，v2.5）

| 流水线 | run | 结果 |
|---|---|---|
| `image` | 155 | 832×1216 PNG，0.79 MB，verify-media 通过（WARN 仅"无音频"属正常） |
| `image` + `qc` | 156 | 质量循环 1 轮 score=100；外层 `start→quality_loop→end`，临时图跑完即删 |
| `video`（H3，optimize=false） | 157 | 5.167s / 124 帧 / h264 + AAC 32kHz 立体声，响度 mean −18.8 |
| `image_batch`（LLM 拆镜） | 160/161 | 4 张分镜图；**冷启动**（引擎先起、Ollama 后起）也能跑通 |
| `voice`（TTS） | 162 | 5.99s wav 44.1k 单声道；ASR 回读"雨夜旧客栈,油灯江西,师徒二人隔桌而坐…"（"将熄"→"江西"是 ASR 同音错，不是 TTS 念错） |
| `film`（2 镜 / 10s 目标） | 163 | 9.6s / 228 帧 / 带声 / **ASR 空 = 无对白**（与设定一致）；verify-media 全过；shotlist 13.2 分钟 |
| `image_edit` restyle | 177 | 608×352 底图按强度 0.85 重绘，出图成功 |
| `image_edit` inpaint | 178 | 自建 608×352 黑底白框蒙版；未遮区域保持原样、遮罩区被重画（默认 flux-schnell 属弱修补，专业重绘要换 Fill 模型） |
| `image_edit` upscale | 170 | 640×960 → **2560×3840**（4×，6.92 MB） |
| `video_from_image`（t2i → 2 段 H3） | 172 | 10.168s / 244 帧 / 带声 / ASR 空；verify-media 全过；含排队约 7.7 分钟 |
| 队列不阻塞 | 174/175 | 连发两条 produce，各 **1.55s** 返回（1.5s 是依赖探活），都正常入队执行 |

首跑暴露并已修掉的四个真问题（都有回归测试）：

1. **`Startable` 把子命令当脚本**：`ollama serve` 的 `serve` 被 `os.Stat` 判成"脚本不存在"，
   进程根本不派生；且 `Start` 分支没写 `last_error`，界面只回 202 什么都不说。
   → 现在按"看起来像路径"才做存在性检查（`looksLikeScriptPath`），不可启动一定留下原因。
2. **引擎先起、Ollama 后起 → 默认模型错配**：启动时探不到模型就退到兜底名，
   之后每个 LLM 调用都 404。→ 404/model-not-found 时对**默认模型**重新挑一次真存在的再试一次
   （调用方点名要的模型绝不替换），并把模型名与原始响应写进错误。
3. **PNG 被当成视频**：ffprobe 把 png 报成一个 1 帧视频，质量循环把图挂在 `video` 键上，
   需要图片的下游就找不到。→ 按扩展名纠正 `kind=image`。
4. **引擎日志掉进管道**：常驻时 stdout 被父进程吃掉，出事后一行都读不到。
   → 现在同时写 `<exe目录>/logs/engine.log`（8MB 滚一份 `.1`）。
5. **默认并发 2 等于让两条片互杀**：首跑时 film（H3 占 23.6GB）与一条文生图并行，
   后者直接撞 5m15s 节点超时（看着像"图片节点坏了"）。→ 默认并发改 **1**，
   真要多卡再 `FLOWEDGE_QUEUE_CONCURRENCY` 显式开。
6. **队列的 Enqueue 会阻塞 HTTP**：旧实现 `sem <- struct{}{}`，槽位满时 produce 请求
   卡住不返回（客户端 60–180s 超时，而任务其实在排队）。→ 改成入队+调度，
   Enqueue 立即返回（实测连发两条 produce 各 1.55s，且都进了队列）。
   四条队列回归测试钉住：不阻塞 / FIFO / 并发上限 / 关闭后拒收。

## 五、没做的 / 已知限制（诚实清单）

- **七条流水线都真跑过一遍，但没做质量调优**：首跑证明链路通（见上表），
  不等于"每种题材都好看"。H3 单镜在这台机上实测 **约 6.6 分钟/镜**（608×352×124 帧 @12 步，
  含冷加载），比旧文档记的 ~2 分钟慢得多——那是不同参数/实例下的数字，别拿它估时。
- **前端只在 jsdom 里测过**：真实浏览器里的布局与交互未经人工目视。
- **一致性门换了位置，没丢**：旧的 `consistency_gate` 节点吃的是"已生成的多段视频"
  （抽帧算签名），跑完 40 分钟才告诉你前面白拍，而且只能人工接在画布上。
  现在改成 `shotlist` 的 **plan 级门**（`service/consistency_plan.go`），开机前审分镜表：
  `continue` 续接却跳轴/换光比 → FAIL；场景锁句字节不全等 → FAIL；环境声多写法 → WARN。
  不做的是"抽帧比对"这一层（`consistency.go` 已删）；真需要时按
  `AuditPlanConsistency` 的接口加，而不是把节点加回来。
- **旧的工作流数据仍在库里**：`workflows` 表还在（只用于质量循环临时图），
  历史工作流记录没删（不占运行路径，只是历史）。
- **旧文档还有画布口吻**：`docs/多模态出片手册.md`、`AGENTS-实现档案.md`
  描述的是画布时代，代码层面已不适用；出片前按本文 + 手册里的
  参数/验收章节看，别按"建工作流"那套操作。

## 六、怎么用

```bash
# 1) 起引擎（常驻，不在 agent 沙箱内）
python scripts/ensure-daemon.py

# 2) 我能出什么
python scripts/run-flowedge.py pipelines

# 3) 出图（带质量循环）
python scripts/run-flowedge.py produce --pipeline image --params '{"prompt":"云海之上的中式楼阁，黄昏","qc":true}' --wait

# 4) 5 秒带声音的视频
python scripts/run-flowedge.py produce --pipeline video --params '{"prompt":"白鹿立于雪峰，慢推，风声与铃响"}' --wait

# 5) 30 秒多段短片
python scripts/run-flowedge.py produce --pipeline film --params '{"prompt":"雨夜旧客栈，师徒对峙，无对白","seconds":30,"max_shots":6}' --wait

# 6) 冒烟（不触发真实生成）
#    6a) 验「正在跑的实例」：内部起引擎 + 接口断言
python scripts/check-all.py --live
#    6b) 验「刚构建出来的成品 exe」：隔离端口、deps 全不自动启动、不碰线上实例
python scripts/verify-exe-isolated.py
```

改流水线：编辑 `data/pipelines.json` → `POST /api/pipelines/reload`（或重启）。
改完记得 `python scripts/check-all.py`——`pipeline_test.go` 会拿真文件逐条组装。

### 部署（有个新坑）

流水线定义在 **exe 目录的 `data/pipelines.json`**，缺它引擎会直接拒绝启动（`log.Fatalf`，
错误信息给出该复制到哪个绝对路径）。构建会把一份放到 `dist/data/`；
`运行/3-应用更新并重启.bat` 已内置「同步 data/pipelines.json」这一步。
手动换 exe 时**记得一起复制这个文件**——只换 exe 会得到一台起不来的引擎，而这看起来像"新版本坏了"。
