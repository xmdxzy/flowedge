## 2. 「万物皆可模块」在代码里是什么样

一个模块 = 四元组，逻辑和模态完全同构：

```
Inputs(端口) → KeyParams(参数) → Outputs(端口)
                     ↑
              Requires(要什么服务) / GateLayers(能挂哪几层门)
```

- `if_else`（逻辑）：`in text → out text + branch(text)`
- `text2image`（模态）：`in text → out image`
- `tts`（模态）：`in text → out audio`
- `aggregate`（逻辑）：`in any → out text + json`

引擎**不写"哪些节点能接哪些节点"的白名单**，只判断端口类型：
`PortKindAccepts(from, to)` —— 同类型互通，`any` 与任何类型互通。这就是"强组装"的最小规则。

三条硬约束由测试守住：

| 约束 | 测试 |
|---|---|
| 注册了执行体就必须有契约，有契约就必须有执行体 | `TestModuleContractCoversRegistry` |
| `spec.go` 不许出现**任何**节点类型字面量 | `TestSpecCompilerHasNoTypeSwitches` |
| `preflight.go` 不许 `switch n.Type` / `n.Type ==` | `TestPreflightHasNoTypeSwitches` |

## 4. 任务书的三条铁律（写进 AGENTS §5.13.1）

1. **只报事实**：参数值取 `node.data` 真实写的，不补默认值。默认值住在引擎与 `data/models.json`，
   复制一份就是第二份真相（「涡轮 8 步 vs 实际 12 步」的教训）。
2. **不确定就写出来**：无契约 / 孤立节点 / 必填输入没来源 / 成环 / 声明门层却无阈值 → `Warnings` + §5。
3. **门必须有牙齿**：声明了门层却没阈值 = 等于没设门，必须告警。

> 临时实例用完即停（`TaskStop`），未动 8080 上正在跑的引擎，也未覆盖 `运行\FlowEdge.exe`（文件被占用）。

**修掉的两个真 bug**（都是自己写的，被真实产物抓出来）：

1. **端口按节点 id 查表**：`resolveOutputPort(e.Source, …)` 传的是 id 不是 type，
   恒返回 `out/any` → 端口不匹配永远检测不出来，任务书上的「输入」全是假的。
   现在按源节点类型解析，并加了 `TestSpecResolvesPortsBySourceType`。
2. **门段落自相矛盾**：模块声明了 5 层门、却渲染成"没有任何模块声明门层 → 没有自动验收"。
   现在区分三态（无门层 / 有门层无阈值 / 有阈值），并把中间态升级为 Warnings。
3. **端口 JSON 字段大写**：`Port` / `KeyParam` 没有 json tag，`/api/modules` 输出 `Name/Kind/Required`，
   与其余 API 的 snake_case 不一致。已补 tag，并在 18080 真实实例上核对过原始响应。
