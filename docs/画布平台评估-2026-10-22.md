## 2. 四件事还不成立（逐条带证据）

### 2.1 卡片是"标签卡"，不是"产物卡"

全仓 `frontend/src/nodes/` 里 **`<img>` 与 `<video>` 出现 0 次**（`grep -n "img\|<video" *.tsx` 只命中一句注释）。

- 文生图卡片：图已经生成了，卡片上渲染的是文字 `🖼️ 已生成`（`Text2ImageNode.tsx:43-47`），
  提示词被 `truncate max-w-[200px]` 截断。
- 视频合成卡片：内容区是**静态硬编码**的 `图片 + 音频 → 视频`（`VideoNode.tsx:32-34`），
  跑完也不显示时长、帧数、有没有音轨。
- 子工作流卡片：只显示一个名字（`SubWorkflowNode.tsx:38-41`），不显示它会产出什么。

后果：**你无法在画布上"看"这条流水线的状态，只能看颜色点**。
判断产物对不对，必须切到右侧"输出"Tab 看裸 JSON，或者开 Gallery 找文件。
这是"卡片式平台"和"节点图编辑器"的分界线——卡片没有承载产物，它就只是带颜色的方块。

### 2.2 "改详细任务"的主入口是裸 JSON 文本域

`shotlist`（分镜执行）节点最核心的"分镜表"，在属性面板里是一个 `textarea`：

```
分镜表 JSON（留空取上游 plan）
<textarea rows={5} value={node.data.plan} ...>
```
—— `NodeInspector.tsx:865-875`

也就是说：你要"在画布上随意修改具体单元流程和详细任务"，实际动作是**在一个小文本框里手写/改 JSON**。
分镜表真实结构含 `segments[] / lead / lines[] / voice / speed / pause / prompt / frames`
（见 `data/film/huanggui/plan.json`，125 行），手改极易破格式，而且**没有任何字段级校验反馈**。

同类问题：`comfy_workflow`（整段 workflow JSON）、`scene_grid`（九宫格）也是文本域/纯文本。

### 2.3 模块层级只有"视觉分组"，没有"可复用模块"

| 现有 | 实际是什么 | 缺什么 |
|---|---|---|
| `group` 节点 | 一个虚线框 + 标题（`GroupNode.tsx` 全文 18 行） | 不能折叠成一张聚合卡、没有边界端口、不能另存复用 |
| `sub_workflow` 节点 | 存一个 `workflow_id` + 名字，运行时调另一条已存工作流 | 无输入/输出端口契约、不能在画布内展开、改内层要跳出去 |

所以现在的"模块化"= **命名 + 引用**，不是**封装 + 契约**。
真要"模块式"，`group` 收起后应该变成一张卡（模块名 / 端口数 / 聚合状态 / 最慢节点），
点进去是面包屑下钻；`sub_workflow` 要有显式 `inputs[] / outputs[]`，否则复用的永远是黑盒。

### 2.4 门控：引擎侧很强，画布侧隐形，而且是两套

**事实一：前端 `grep -rn "gates" frontend/src` = 0 命中。**
五层门（timing / identity / audio / technical / budget）只存在于 `scripts/film-gates.py` + `plan.json`：

```json
"gates": {
  "profile": "duel-30s-3shot",
  "timing":  { "grid": [5,17], "target_seconds": 30.0, "beat_weights": {...} },
  "identity":{ "stills": 2, "require_ref_images_every_segment": true, "require_picture_tags": true },
  "audio":   { "dialogue": {"must_transcribe": true}, "loudness_db": [-20,-11], "max_silence_gap": 0.8 },
  "technical":{ "min_width": 608, "av_drift_max": 0.2 },
  "budget":  { "wall_seconds_max": 1500, "per_segment_wall_max": 600 }
}
```
—— `data/film/jindan/plan.json`

只有开终端跑 `python scripts/film-gates.py check` 才看得到 verdict。**画布上完全看不见**。

**事实二：画布上的"门"是另一套东西。**
`quality_gate` 节点 = 9 个扁平数字（`NodeInspector.tsx:630-694`）：
`min_frames / duration_min / duration_max / min_width / min_height / duration_tolerance / max_silence_gap / loudness_min_db` + 两个开关。

它**没有层概念、没有 profile、没有 beat 权重、没有 identity 检查（定妆图/参考图/<Picture N> 越界）、没有 budget**。
两套门不共享 schema、不共享校验器、不互相知道对方存在。

> 这是"门控是否易懂"最致命的答案：**人在画布上看到的门，和真正拦截出片的门，不是同一个门。**
> 你没法在画布上回答"这条片子为什么没过门"。

**事实三（顺带查到的）**：卡片文案与实现不一致。
`shotlist` 面板写 `涡轮 LoRA（8 步）`（`NodeInspector.tsx:894`），
而引擎 `comfy_media.go:530` 已把 turbo 默认步数从 8 提到 **12**（低于 12 音频会乱语），
`text2video` 面板自己也写的是 `20 步 → 12 步`（`NodeInspector.tsx:1267`）。
同一引擎、两个面板、两个数字。**已修**（本轮改为 12 步并注明原因）。

### 2.5 智能体只能"遥控"，读不到"说明书"

MCP 现有 5 个工具（`backend/mcp/server.go:306-364`）：

| 工具 | 能力 |
|---|---|
| `flowedge_list_workflows` | 列工作流 |
| `flowedge_run_workflow` | 提交运行（workflow_id + vars） |
| `flowedge_run_status` | 查 run 进度与产物路径 |
| `flowedge_estimate` | 预估显存/耗时 |
| `flowedge_generate_image` | 单张出图 |

**缺的是"读"和"写"这两类**：

- 没有 `get_workflow` → agent 不知道画布上有哪些节点、连成什么顺序、每个节点什么参数。
- 没有 `get_spec` / `export_plan` → 拿不到一份"照着做"的任务书。
- 没有 `patch_node` / `update_workflow` → agent 不能按你的新要求改图。
- 没有 `get_gates` → agent 不知道验收标准，只能跑完说"成功了"。

前端也只有 `导出 JSON`（`App.tsx:1376`）——那是给 FlowEdge 自己导入用的机器格式，
不是给人或 agent 读的规格。

**这就是你要的"画布指导智能体工作"的缺口：画布是给人看的，引擎是给机器跑的，中间少一层编译。**

## 4. 优化路线（按杠杆排序，不是按工作量）

### P0-A｜Workflow Spec 编译层 —— 唯一直接回答第 4 问的改动  ✅ 已落地（2026-10-22，见 `docs/交付-模块契约与任务书-2026-10-22.md`）

新增 `GET /api/workflows/:id/spec?format=md|json`：

```
输入：nodes + edges + NodeSpecs（已有）+ 上游产物字段（已有 NODE_OUTPUT_FIELDS）
输出：一份 Markdown 任务书
```

固定结构（每段都要能被人和 agent 同时读）：

```markdown
# 工作流：古装短剧 30 秒 · 3 镜

## 执行顺序（拓扑分 4 层；同层可并行）
| # | 节点 | 类型 | 输入 | 关键参数 | 产物 | 门 |
|--|------|------|------|----------|------|----|
| 1 | 剧本拆解 | storyboard | start.text | 3 镜 / 竖屏 | plan(JSON) | — |
| 2 | 定妆图 | text2image | — | 1024²×2 / 12 步 | image×2 | min_width≥1024 |
| 3 | 分镜执行 | shotlist | plan + image×2 | 608×352 / 124 帧/镜 | video×3 | 五层门见下 |
| 4 | 后期包装 | post_production | video + bgm | 1080×1920 / duck on | final.mp4 | 帧数=计划帧数 |

## 验收门（任一 FAIL 即不许交付）
- timing.max_shot_seconds = 4.5
- audio.dialogue.must_transcribe = true（台词必须转得出原话）
- technical.av_drift_max = 0.2s

## 产物清单
- data/generated/{run_id}/final.mp4

## 不要做的事
- 不许改 SCENE LOCK 文本（逐字注入，改一个字节接缝就换场地）
```

配套两件事：
1. MCP 加 `flowedge_get_spec`（+ `flowedge_get_workflow` 返回节点/边 JSON）。
2. 前端在 `导出 JSON` 旁边加 **`导出任务书`**，同一份 Markdown 直接落盘。

**验收**：把这个 md 丢给 workbuddy，它能不问你一句就把片子跑出来。
工作量 **2–3 天**（后端 250 行 + 契约测试 + 2 个 MCP 工具 + 1 个按钮）。

### P0-B｜卡片说真话、出缩略图

1. 卡片从 `data.output` 取真实产物：图给 `<img>` 缩略（64px 高）、视频给首帧 + 时长/帧数徽章、音频给时长。
2. 把"生效参数"回填进 `node.data`（后端已有 `output` 通道），别让前端猜默认值。
3. 加一条**文案一致性测试**：面板上写的默认步数/模型名，必须等于引擎实际值。
   这次的"8 步 vs 12 步"必须能被测试抓住，而不是靠人眼。

**验收**：画布上不用点任何面板，靠卡片就能判断"这条跑对了没有"。
工作量 **1 天**（卡片是共享组件，改 3 个基类即可）。

### P1-A｜门控单一来源（把五层门搬进画布）

1. 门 schema 抽成单一来源（`data/gates-schema.json`，Go 读、前端生成 TS 类型）。
2. `quality_gate` 节点升级为"能挂一层门"：`layer: timing|identity|audio|technical|budget` + 该层阈值。
3. run 结束时把 `film-gates.py` 的 verdict 通过 `POST /api/runs/:id/gates` 回写，
   画布上每个门节点显示 green / amber / red + 第一条 FAIL 原因（点开看全部）。
4. 前端**只渲染后端给的 verdict，不重写判定逻辑**（避免第二份真相）。

**验收**：片子没过门时，画布上直接标红并写出"第 2 段台词 ASR 转不出 → audio.dialogue FAIL"。
工作量 **2–3 天**。

### P1-B｜真模块（分组可折叠 + 子流有契约）

1. `group` 收起 = 一张聚合卡（模块名 / 输入输出数 / 聚合状态 / 最慢节点），双击面包屑下钻。
2. `sub_workflow` 增加显式 `inputs[] / outputs[]`，连线时做类型校验。
3. "选中一组 → 另存为子工作流"。

**验收**：一条 20 节点的片子，收起后画布上剩 4 张模块卡，且每张卡能说清"吃什么、吐什么"。
工作量 **3–5 天**。

### P2｜卡片数据驱动（彻底解耦）

`NodeSpecs` 加 `Params []ParamDef`，前端用一个渲染器替掉 `NodeInspector.tsx` 里 40 处 `node.type ===` 分支。
特殊控件（分镜表、九宫格、参考图选择）保留 custom widget。
**这是治本，但必须先把 P0/P1 做完**——否则等于给一个还没定型的表达层做序列化。
工作量 **5–7 天**。

## 5. 如果只做一件事

**做 P0-A（Spec 编译层）。**

理由：它同时解决三件事——① 你要的"指导 agent"直接成立；② 门控第一次有了人能读、agent 也能读的统一表达（任务书里必须写门）；③ 顺带把"这条流水线到底在干什么"变成可 diff、可 review、可进版本库的东西。

P0-B 是它的前置佐料（卡片不显示真实产物，任务书里的"产物"就没人对得上），建议同批做。
