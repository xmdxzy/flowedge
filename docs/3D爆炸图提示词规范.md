# 3D 爆炸图提示词规范（H3 文生视频 · 产品结构解构）

> 触发条件：画面里出现**产品逐层分离 / 悬浮拆解 / 结构展开 / 部件归位**的任何镜头。
> 金标准来源：用户提供的机械腕表 12 秒宣传片提示词（2026-11-03），
> 经 [MiniMax H3 官方 prompt guide](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)
> 与 [官方极简产品广告 Skill](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/minimalist-product-ad-generator/SKILL.cn.md) 逐条核对。
> **出片前必跑** `python scripts/check-prompt.py <plan.json>`，FAIL 不许提交。

## 一、结构：三段字段，字段名是字面标签

H3 的 AV 一体化（画面 + 音效 + 配乐同一次推理）靠**三个字段**，不是靠正文里提到声音：

```
integrated_multimodal_description: [Shot 1] <风格句> <初始构图> <主体外观与位置> <动作> <该刻画内声>

overall_soundscape: <1–4 句>

non_diegetic_music: <1–3 句>
```

| 字段 | 官方定义 | 硬约束 |
|---|---|---|
| `integrated_multimodal_description` | visuals, actions, shots, speakers, dialogue, singing, and **diegetic audio along the timeline** | 与某一镜头同步的音效**写在这里**，不写在 soundscape |
| `overall_soundscape` | ambient sound + physical action sounds + non-verbal human sounds **across the entire video** | **1–4 句**，一段连续文字；`Dialogue… should not be repeated here` |
| `non_diegetic_music` | 角色听不到、只有观众听得到的配乐 | **1–3 句**；只写乐器/速度/节奏/动态，官方明令 `do not use abstract mood words` |

**字段名必须逐字出现**（含冒号）。只在正文里写「声音：……」而漏掉 `overall_soundscape:` / `non_diegetic_music:` 两个标签 = 模型自行脑补，含即兴人声。这是引擎体检 `soundscape_missing` / `music_missing` 的 FAIL 项。

**正文必须英文**。官方 ref guide 首段与 [ComfyUI 官方文档](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-prompt-guide) 都这么要求；只有画面内文字与台词保持原语言。中文正文不是「不能用」，是**语义权重会漂**——本地 `scene_grid.go` 对锁句的注释写得很直白：「H3 正文一律英文」。

**切点写法**：`[Shot 1]` **不加**时间戳；后续镜头 `[Shot 2] At 00:04.000, the camera cuts to …`。中文「在 00:04.000」不合规。切镜动词只有五个官方选项：`the camera cuts to` / `the shot cuts to` / `the shot transitions to` / `the shot changes to` / `the shot switches to`。

## 二、爆炸图的七条专属规则

### 1. 分离顺序 = 装配顺序的倒序

外部先走，内部后走。腕表：表镜 → 表盘/指针 → 机芯 → 底壳。台式机：侧玻璃 → 前脸/顶盖 → 主板 → CPU+散热器 → 内存 → 显卡 → 电源/SSD/风扇。

出处：[Wikipedia exploded-view drawing](https://en.wikipedia.org/wiki/Exploded-view_drawing)「the parts on the outside normally get removed first」+ [open-3d-skills](https://github.com/Moh4696/open-3d-skills)「Take things apart the way a mechanic would」。

**归位时必须反过来按装配正序**，并逐件点名。腕表片没写这条，回收段就出现了「层顺序含糊」。

### 2. 每个部件一个专属运动动词，不许共用「移动」

金标准之所以读起来清楚：`浮离 / 升起 / 水平展开 / 左右摆动 / 咬合转动 / 缓慢释放 / 呼吸般收放`——七个部件七个动词，动词本身就是该部件的物理职责。表镜只能「浮离」（它是平面玻璃），游丝只能「收放」（它是弹簧）。

### 3. 沿单一装配轴平移；壳体离轴让位

大壳体（侧板/上盖）**沿水平轴向外**，与垂直堆叠的内构分道，这样核心始终可见。所有内构层**等间距**排在一条直线上。

### 4. 运动源 ≤ 2 个（这条腕表片违反了）

相机与部件不能同时各自运动。社区失败表首行就是 `Parts spin or orbit` → 对策「separate by translation only along one straight axis; no rotation」。

正确分工：**只有会工作的机构在到位后继续动**（风扇叶轮、摆轮、齿轮、游丝），其余部件纯平移、停住即静止。相机要么 `Static Shot` 要么单一 `Push In`/`Arc Shot`，二选一。

腕表片写了「相机慢速环绕 + 各部件各自缓慢自转 + 部件间引线相连」= **三个运动源叠加**，这是它画面发散的根因之一。

### 5. 引线是「部件 → 标签」，不是「部件 → 部件」

正统工程制图里，部件之间的分组用**括号 embrace**（[37 CFR 1.84(h)(1)](https://www.law.cornell.edu/cfr/text/37/1.84)），连线（leader line）永远从部件指向**编号气泡**。腕表片把引线画成部件互连（装饰性），读起来像悬挂结构而不是标注系统。

写法：`a single hairline white leader line runs from each component rightward to a small white numeral, 01 through 07, stacked top to bottom along the right third of the frame; every label sits clear of the hardware`。

### 6. 件数必须显式钉死

扩散模型不会数数。`Exactly seven separated components are present` + 逐件点名，否则件数每帧漂。层数压到 **5–8 个粗层**，太细会融层穿模。

### 7. 编号要**逐字枚举**；归位段要**按帧数预算砍拍**

`01 through 07` 会被渲染成 `01 02 04 05 06 07`（run 431 实测漏 03）。序列是概率的，枚举是查表的：
`reading 01, 02, 03, 04, 05, 06 and 07 in order`。

归位段拍不完的**根因是动作密度，不是措辞**。run 431 的镜 3 已经写了
`stands whole` + `every panel flush`，检查器一度以为"措辞齐备=安全"，结果仍拍成开口机箱——
73 帧（3.04s）塞了 5 类动作（层归位 / 面板闭合 / 相机拉远 / 高光扫过 / 淡出）。
经验预算：**一镜可靠承载 ≈ 帧数 ÷ 35 拍**（107 帧≈3 拍）。修法是把**淡出与高光扫过交给后期 ffmpeg**
（零成本），或加帧到 175（7.29s，上限 362）。

`scripts/check-prompt.py` 第 10 条按**类别**计数（同类只算一次）——按动词计数会把 5 拍报成 14 拍，
虚高的门必然给出荒谬建议（曾算出"加帧到 490"，而 H3 上限只有 362 帧）。

## 三、画面内文字：三条硬约束（腕表片违反了第 3 条）

1. **英文双引号包裹原文**，逐字保留标点，不翻译（官方 §4.5，例：`A red neon sign reading "营业中"`）。
2. **同一时间只允许一条单行文案**。官方产品广告 Skill 原文：「禁止上下两排文字、双行标题、主副标题并列或多处文字同时出现。两段式文案也必须在同一行内接续或替换」。
   → 腕表片的 `"72H"` + 下一行 `"Automatic Movement"` **正是上下两排**，属违规。台式机片改成单行 `"Built For Airflow"`，前半白色后半商品色，走官方要求的「两段式同行接续 + 轻位移」动效。
3. **3–5 个英文词，≤32 字符含空格**；写字体 `SF Pro Display Semibold`；位置在上下居中的构图区、靠左或靠右成为画面元素，**不要放下方字幕位**。文字易错就**减少出现次数**，10 秒片通常只留 1 次中段 + 1 次结尾。

## 四、保真与「不要品牌标识」：必须写成正面事实

**cfg=1 没有负向分支**。写「表面无任何品牌标识与文字」不但无效，还会把 `品牌标识 / 文字` 这个概念**注册成内容**——腕表片三镜都写了这句，结果表盘 12 点位长出伪品牌字样 + 假 logo，而**同一片段里被正面要求写 `"72H"` 的镜 2 反而准确渲染了文字**。同一次 run、同一模型、一正一反，这是本项目最硬的一条实测证据。

写法：描述**表面是什么**，不是描述**表面缺什么**。

| 否定式（无效） | 正面事实（有效） |
|---|---|
| 无任何品牌标识与文字 | `every visible face reads as bare brushed metal, glass and matte unprinted plastic` |
| 不要出现 logo | `the panels are blank and featureless, the glass is clear and unmarked` |
| 没有多余零件 | `each one distinct and whole` |
| 不许旋转 | `every other surface stays fixed in place` |

**注意豁免表是有害的**：`scripts/check-prompt.py` 里曾有一份「正向否定白名单」（放行 `no component is duplicated`），已删除。一条带例外的规则就是会被破的规则——要表达约束，就换成状态描述。

**图内有字要不要换后端**：文生**图**阶段的可辨认文字必须走 MOSS（flux 只会画「像字的笔画」），见 `docs/出片硬约束/31-文字-图内有字必须走MOSS.md`。H3 文生视频的画面内文字是另一回事——它由 `integrated_multimodal_description` 里的双引号原文驱动，能力上限低于 MOSS，所以更要靠「少写、写短、写单行」。

## 五、时长与帧数网格

H3 帧数必须落在 `17k+5`（73=3.04s / 90=3.75s / 107=4.46s / 124=5.17s / 141=5.88s）。**「12 秒」不在网格上**，能落到的组合是 107+107+73=283 帧（装配吃 2 帧硬切重叠 → 11.79s）或 107+124+73=304 帧。差的那 0.2s 用后期 `tpad` 补黑 + 淡出对齐到整 12.000s，零显存。

分辨率：本机 H3 实测最高安全档 **736×416**（比 = 1.769）。要严格 16:9（1.778）就在交付阶段 `crop=736:414`，2px 的事，不必重渲。

## 六·五、中文标注必须后期烧，不交给模型（run 432 定案）

**要标出模块名时，画面里一个中文字都别交给 H3。** 官方 §4.5 的中文范例是
`A red neon sign reading "营业中"`——单条、粗体、发光大字。7 条细体小字同时在场是另一个量级的难度：
字形能力来自训练数据的字形条件，汉字笔画密度又远高于拉丁（同一片里 `"Built For Airflow"` 逐字正确，
换成 7 条中文就是赌）。要「不糊」只有一条路：**libass 后期烧录**。

提示词侧的配合写法（正面描述，不是"不要编号"）：

```
a single hairline white leader line runs rightward and ends in open empty space
beside the stack, seven lines stacked top to bottom along the right third of the
frame with clear room at every line end for a label to sit later
```

这样模型只画**纯几何线**（它擅长，实测很规整），末端留白给标签落位。

### 后期烧录的四个坑（每个都真烧过一次）

| # | 坑 | 症状 | 正解 |
|---|---|---|---|
| 1 | **ASS 时间戳是厘秒 2 位** `H:MM:SS.cc`，不是毫秒 3 位 | 「7 条标签只出 1 条，而引线全在」；时长/帧数/音频/门控**全部正常** | `cs()` 统一格式化；写 `.833` 会被读成 8.33 秒，事件轴整体错位 |
| 2 | 用统一时间的对照实验**看不出坑 1** | `.000` 按厘秒和毫秒解析都是 0，于是"改了时间就好了"，误诊成 `\fad` 的问题 | 对照实验必须**只改一个变量且该变量非零** |
| 3 | `\an6` 是右对齐锚点 | 文字从锚点向左铺，**正好压在引线末端** | 文字要在引线右侧 → `\an4`（左对齐 + 垂直居中） |
| 4 | `\N` 双行块高 ≈27px | 顶盖引线 y=73、电源层中心 y=84，**两层只差 11px** → 两行挤成一团 | 改单行内联字号 `中文{\fs10} 英文`，块高降到 17px |

### 标签落位一律实测，不许按经验排

模型只画了 **5 条**引线（y=73/132/181/248/303），而结构有 7 层——「电源与硬盘」「机箱底壳」没有线。
缺线的层**补画**（`\p1` 矢量），起点取该层实测右缘（在 x<0.72W 内找**连续 ≥4 行都亮**的最右列，
以排除细引线本身、又不截断宽扁的底壳）。已有线 ±12px 内吸附，避免双线。
**引线指向实测层位 y，标签可因最小间距 19px 让位**——线贴部件才有指代关系，字可以错开（工程图常规）。

停留窗口与层位用 `scripts/probe-exploded-hold.py`（逐帧差分找静止段）与
`scripts/probe-exploded-layers.py`（亮度投影找层中心）实测；
**`scripts/make-exploded-labels.py` 是这套管线的唯一事实源**——改版式改脚本，
不在 `.ass` 产物上手改（手改会被下次重跑静默覆盖，产物与脚本漂移）。
范例分镜表：`data/examples/pc-exploded-plan.json`。

## 七、实测记录（run 431，台式机 3 镜 283 帧 / 736×416 / 10.0 分钟）

按本规范写的第一支片子。逐条对照，**规范有效的证据**：

| 规范条目 | 结果 |
|---|---|
| 表面写正面状态（`bare brushed metal, blank and featureless`）替代「无品牌」 | ✅ **全片零伪品牌字样**（对照 run 430 腕表片三镜都长出假 logo） |
| 画面文字单行 + 3–5 词 + 双引号原文 | ✅ `"Built For Airflow"` 逐字正确、单行、白+银两段配色 |
| 引线「部件→编号」自上而下竖排 | ✅ 细白引线 + 右三分之一竖排编号，标签不压部件 |
| 件数钉死 `exactly seven` | ✅ 爆炸段 7 层齐备，无融层无穿模 |
| 运动源 ≤2（相机 Static + 仅风扇叶轮转） | ✅ 无翻滚、无抖动，比腕表片明显干净 |
| 分离=装配倒序 / 归位=正序 | ✅ 侧玻璃与面板先出、主板先归位 |

**新暴露的两条规范缺口**（下次必须写进去）：

1. **编号必须逐字列出，不能只写 `01 through 07`**。实测渲染出 `01 02 04 05 06 07`——**漏了 03**，
   6 个标签对 7 个部件。模型对「序列」的执行是概率性的，对「枚举」才是查表式的。
   正确写法：`a small white numeral beside each line, reading 01, 02, 03, 04, 05, 06 and 07 in order`。
2. **归位段拍不完，根因是动作密度不是措辞**。实测镜 3 结束时侧玻璃仍未闭合，画面是
   「开口的机箱」而不是「完整产品」。**注意：提示词里 `stands whole` 与 `every panel flush`
   两句都写了**，所以「补一句终态描述」是错的归因（我第一版就是这么写的，差点固化成假规则）。
   真因：73 帧里塞了 5 类动作（层归位/面板闭合/相机拉远/高光扫过/淡出），
   按「帧数÷35 ≈ 2 拍」的预算根本装不下。修法见 §二.7。

**门控抓不到的两类问题**（`verify-media` 全绿仍要目视）：
- **色温漂移**：镜 1/2 冷灰、镜 3 背景转暖棕。plan 层的 `light` 三镜写的是同一句，
  但镜 3 是「极浅景深特写」，虚化背景把暖色补光放大了——这是生成侧漂移，
  出片后的 `plan.color_shift` 门（U/V 均值）本次未报（相邻镜均值差 <6）。
  对策：镜 3 的 `light` 里显式写 `the same cool neutral background, no warm bounce`。
- **终态构图**：时长/帧数/响度/静音全部正常，画面却是半成品。见 §六清单最后一条。

## 八、未解决（不要用「应该可以」糊过去）

1. **「音乐节奏对齐到滴答频率」官方无条款**。§4.7 只允许写 rhythm/tempo，没有任何示范把配乐对齐到音效频率。腕表片那句是合规推断，效果未验证。
2. **切点精度官方不保证**。社区实测：切点接近但有偏差，要求精确时应在剪辑阶段校实际切点。
3. **云 API 与本地 ComfyUI 对负向提示的结论互相矛盾**：[fal.ai 指南](https://fal.ai/learn/devs/minimax-h3-prompting-guide) 称负向「unusually effective」，[Comfy 官方文档](https://docs.comfy.org/tutorials/video/minimax/minimax-h3-prompt-guide) 第 8 条称 cfg=1 下负向会把概念注册成内容。**两者采样链路不同**，本项目跑本地，按 Comfy 这条走。两条路径不许共用同一段文本。
4. **`generate_audio` 参数查无公开定义**（官方 Skill 文本里出现，API 参数表里没有）。
5. HF 与 GitHub 两份指南是否有版本漂移未逐字 diff；官方 README 自述「guidance 未复制进仓库」，**以 HF docs/ 为权威**。
